# 中文提示词专有坑 — 判据与改法

改中文提示词时逐条扫。每条给：**症状 → 判据（怎么一眼看出）→ 改法 → 例**。
这些坑英文提示词里没有，外部优化器（多为英文项目）也不处理，属于中文场景的主要失效来源。

## 1. 软化词削弱约束

- **症状**：规则里有「尽量」「适当」「酌情」「必要时」「尽可能」「适度」「原则上」「基本」。
- **判据**：把句子读成"违反了算不算错"——答不出来就是软化词在放水。
- **改法**：换成可判定的阈值、数量或动作。实在要保留弹性，就把弹性写成条件：「若无数据，标『待补』」。
- **例**：`尽量简短` → `不超过 3 句，每句不超过 40 字`；`必要时说明` → `缺数据时必须写「数据缺失：<字段名>」`。

## 2. 开放枚举

- **症状**：「等」「之类」「诸如」「例如」后面没有封闭清单。
- **判据**：能不能枚举完？不能，模型就会自行扩边。
- **改法**：改成封闭清单 + 兜底句：「仅限 A、B、C；其他一律不写，遇到就归入『其他』一行」。
- **例**：`包括进度、金额等` → `仅含：进度、金额、风险三项`。

## 3. 范围含不含本数

- **症状**：「以上」「以下」「不少于」「超过」「达到」混用。
- **判据**：100 万元算不算「100 万元以上」？答不出就是歧义。
- **改法**：写「≥100 万元（含）」「>100 万元（不含）」。
- **例**：`金额 100 万以上需审批` → `金额 ≥100 万元（含本数）需审批`。

## 4. 标点与全半角

- **症状**：中文句子里混英文逗号、句号；引号用英文直引号；破折号用 `--`；省略号用 `...`。
- **判据**：全角标点占比不一致；同一段里出现两种引号。
- **改法**：正文统一全角（，。；：""''、——……），代码、路径、命令、英文术语内部保持半角。
- **例**：`输出格式: 标题, 正文.` → `输出格式：标题，正文。`

## 5. 数字与单位口径

- **症状**：万元与元混用；「百分比」与「百分点」混用；没写小数位；「翻一番」「过半」这类相对表述。
- **判据**：同一条规则里出现两种单位，或换算后与原文对不上。
- **改法**：全篇统一单位并写精度；比率与差值分开表述。
- **例**：`增长 5%` → `同比增长 5.0%（比率）；较上月提高 5 个百分点（差值）`；`金额单位统一为万元，保留两位小数`。

## 6. 代词与指代不明

- **症状**：「它」「该」「其」「上述」「前述」「此」连用，前文有多个候选对象。
- **判据**：把代词替换成名词，句子是否还成立且唯一？
- **改法**：重复名词，或用编号引用（C3、P2、第 4 条）。
- **例**：`将其合并后提交` → `将 P2 与 P3 合并后提交`。

## 7. 序号层级混乱

- **症状**：一、（一）、1.、（1）、① 混用；说「第 3 条」时分不清是哪一层。
- **判据**：跨段引用「第 N 条」是否能唯一定位？
- **改法**：全文最多三层，且只在最外层用「第 N 条」这类引用；层级用固定符号，不混用。
- **例**：一级 `一、二、`；二级 `1. 2.`；三级 `（1）（2）`。

## 8. 指令动词模糊

- **症状**：「处理」「优化」「完善」「把关」「梳理」「跟进」。
- **判据**：这个动词能不能换成一个看得见的动作或产出？
- **改法**：换成动作 + 产出 + 判定。`梳理` → `按金额从大到小列成一张表，缺金额的标「待补」`。

## 9. 否定式指令过弱

- **症状**：「不要写空话」「不要啰嗦」「别下结论」。
- **判据**：模型仍能产出符合字面但违背意图的内容吗？能，就是否定式太弱。
- **改法**：改成正向的、可核查的要求。
- **例**：`不要空话` → `每句必须含数字、日期或具体动作之一；三者都没有的句子删掉`。

## 10. 中英混排与专名

- **症状**：模型名、产品名、工具名大小写与写法不统一；缩写首次出现没展开。
- **判据**：同一实体在文中有几种写法？
- **改法**：首次出现写全称 + 缩写，其后统一用缩写。
- **例**：`workbuddy / WorkBuddy / WB` → 首次 `WorkBuddy（以下简称 WB）`，其后统一 `WB`。

---

## 用法

守卫模式第 1 步（冻结账本）时顺带扫一遍：命中的条目作为「软化 / 开放 / 歧义」类问题进第 3 步的授权清单，不要自己改——它们都属于 C 项，动之前要用户点头。
