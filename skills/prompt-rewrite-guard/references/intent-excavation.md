# 意图反推 · 分类表、问题库与模板

配合 `SKILL.md` 的 **Excavation Mode（E1–E5）** 使用。规则在 `SKILL.md`，这份文件只提供：判定标准、问法、模板、实例。

---

## 一、六类缺口怎么判

对每一类只打三档。**只有 Partial 和 Missing 才生成候选问题**，而且还要再过 E1 的三条（查不到 + 改写法 + 只有他能拍板）。

### G1 目标与完成态

- `Clear`：他说清了「跑完之后，什么东西存在」。例：「出一张能直接贴进周报的三行结论」。
- `Partial`：只有动作没有交付物。例：「帮我分析一下这个数据」。
- `Missing`：只有情绪或抱怨。例：「这玩意太难用了」。

问法要点：问**完成态**，不问动机。「这三行结论谁看？」比「你为什么要写周报」有用得多——后者是聊天，前者决定措辞和术语密度。

好问法：`这份东西交出去之后，对方看完会做什么？`（选项：直接转发 / 开会用 / 存档备案 / 他自己再加工）
坏问法：`你的目标是什么？`（太大，他会答一个更模糊的词）

### G2 对象与范围

- `Clear`：数量、边界、含与不含都说死。例：「我这 4 个项目的立项变更，不含已结项的」。
- `Partial`：只说了有的，没说没有的。
- `Missing`：完全没提。「帮我整理一下材料」——哪些材料？

问法要点：问**边界**，尤其是「明确不含什么」。人天生只描述在场的东西，漏掉的东西永远漏掉。

好问法：`范围就这四个项目，结项的和别的标段都不碰——对吗？`（是/否 + 默认「是」）

### G3 输入与来源

- `Clear`：喂什么、从哪来、多长、脏了怎么办，至少说了前两个。
- `Partial`：说了「贴进去」但没说贴的是什么。
- `Missing`：默认你会魔法变出数据。

问法要点：**先查再问**。文件夹里有没有、表在不在、字段叫什么，这些都能查。查不到才问，且只问一句：「数据从哪拿」。

### G4 输出形态与精度

- `Clear`：格式（表/段/清单）、长度、要不要数字、精度几位。
- `Partial`：说了格式没说长度（最常见的坑——他想要三行，你给三页）。
- `Missing`：什么都没说。

问法要点：这一类的**默认值最该由你定**，因为用户对长度的估计普遍失真。直接给推荐值，让他否掉即可：

`输出长度：三行内 / 一屏 / 不限（推荐一屏，理由是你要在会上念）`

### G5 边界与例外

- `Clear`：说了冲突怎么办、信息不够怎么办、不许做什么。
- `Partial`：只说了正常路径。
- `Missing`：默认一切顺利。

问法要点：问**最坏情况**，一句话就够：`数据里有一项是空的，这时候是要它留空、还是要它标出来问你？`（留空 / 标出来 / 直接跳过，推荐标出来）

这一类如果用户没提，**不要占提问位**，直接给默认值（宁标不留空），写进意图卡让他改。

### G6 取舍与优先级

- `Clear`：说了打架时先保谁。例：「算得对 > 做得全 > 做得快」。
- `Partial`：隐含但没说。
- `Missing`：没有优先级，等于交给模型的最省力路径。

问法要点：给三个具体冲突让他排，别问「你更看重什么」——他会说「都要」。

`这三样通常打架，排个序：快出稿 / 覆盖全 / 每条都能溯源（推荐：溯源 > 全 > 快，理由是这份要给外部看）`

## 二、好问题与坏问题（对照）

| 坏问题 | 为什么坏 | 改成 |
|---|---|---|
| 你想要什么样的输出？ | 开放式，他会把需求原样复述一遍 | 三行结论 / 一屏表格 / 完整报告（推荐一屏，你要在会上念） |
| 你的目标是什么？ | 太大，答案只会更抽象 | 交出去之后对方看完会做什么？ |
| 需要包含哪些内容？ | 把设计工作推回给用户 | 这三块必须有：原因、金额、影响——还缺哪块？ |
| 有什么特别要求吗？ | 「特别」这个词没人会答 | 有没有明确不许出现的东西？比如公司名、金额 |
| 你希望什么风格？ | 风格对提示词的影响远小于结构 | 不用问，按场景定，写进「我替你定的」 |
| 数据是什么样的？ | 能查 | 先查文件，查不到才问「数据从哪拿」 |

## 三、问题库（按场景挑，不要全问）

每题都自带默认值，实际发出的题数受 E3 定档约束。

### 写作类（周报、汇报、公文、公众号）

1. 谁看这份东西，看完会做什么？→ 默认：直属领导存档
2. 长度控制在多少？→ 默认：一屏（约 600 字）
3. 能不能出现真实项目名和金额？→ 默认：可以（他之前用过真实数据）
4. 有没有必须原样保留的句子（比如上级给的口径）？→ 默认：没有
5. 结论放前面还是放最后？→ 默认：放前面

### 分析 / 调研类

1. 结论要指到哪一层：现象、原因、还是下一步动作？→ 默认：原因 + 下一步
2. 允不允许给不确定的判断？→ 默认：允许，但必须标「待验证」
3. 每个结论要不要附来源？→ 默认：要
4. 只分析给的材料，还是允许联网补？→ 默认：只用给的材料

### 代码 / Agent 指令类

1. 这段指令给谁跑：你自己、别的 agent、还是团队共用？→ 默认：他自己
2. 出错时它应该停下来问，还是按默认继续？→ 默认：停下问
3. 有没有不许碰的文件 / 目录 / 命令？→ 默认：只读，不删不改
4. 判断做对了没有，靠什么？→ 默认：跑测试，贴输出

### 日常办公类（邮件、会议、表格）

1. 一次处理一条，还是批量？→ 默认：批量
2. 语气：对上级 / 对平级 / 对外部？→ 默认：对平级
3. 输出要不要能直接复制粘贴进系统？→ 默认：要，纯文本无格式

### 规则 / 流程 / SKILL.md 类

1. 这条规则出过事吗？出过什么事？→ 默认：没出过，属预防
2. 违反规则时谁来发现？→ 默认：没人发现（那这条规则等于没有）
3. 规则之间打架时听谁？→ 默认：更严的那条

## 四、定档实例

| 场景 | 缺口 | 档位 | 实际动作 |
|---|---|---|---|
| 「帮我写个周报的提示词」 | G4 / G2 两个 Partial，其余能查能默认 | **0 问** | 直接出稿，意图卡写 4 条「我替你定的」 |
| 「它老是不按我想的来」 | G1 Missing、G4 Missing、G5 Partial | **轻问** | 一轮 3 问：交出去谁看 / 多长 / 有没有不许出现的东西 |
| 「帮我想清楚我这套考核规则到底要什么」 | G1/G2/G5/G6 Missing，G3/G4 Partial | **深挖** | 一轮 5 问，剩 1 条进待裁决清单 |

判定口诀：**猜错会让整份白写 → 问；猜错只是让他改一句 → 不问，写进「我替你定的」。**

## 五、意图卡模板

```markdown
| 你要的 | 我按这个理解 | 我替你定的 | 还需你拍板 |
|---|---|---|---|
| "帮我写个周报提示词"（原话） | 一段能让 AI 每周三把四个项目的进展压成一屏、带金额和风险的指令 | 长度一屏（查得：你要在会上念）<br>结论放前面（行业惯例）<br>可以出现真实项目名（猜的：你之前用过真实数据） | 无。都不对就改上面三行 |
```

规则：
- 第一列**引用原话，一字不改**。改了就等于替他改了需求。
- 第三列每条都要带 `查得` 或 `猜的`。`猜的` 是他最该看的部分。
- 第四列只在还有高影响缺口没问时才有内容；都定了就写「无」。
- 表里不写解释段落。要解释就写进第三列的括号里。

## 六、完整实例：一句模糊话 → 提示词

**用户原话**：「我想要 AI 帮我写周报，每周三都要弄，烦死了」

E1 查：会话里知道他管四个项目、会上念、用真实数据（`查得`）。

E2 扫：G1 Clear（能念的三行结论）；G2 Partial（四个项目含不含已结项的）；G3 Clear（数据他自己贴）；G4 Partial（长度没说）；G5 Missing（数据缺项怎么办）；G6 Missing（快/全/准）。

E3 定档：高影响缺口 2 个（G2、G4）→ **0 问档**。

**交付**

意图卡：

| 你要的 | 我按这个理解 | 我替你定的 | 还需你拍板 |
|---|---|---|---|
| "我想要 AI 帮我写周报，每周三都要弄，烦死了" | 一段固定指令：每周三把四个项目的进展压成一屏，带金额和风险，能在会上直接念 | 只含在建的四个项目，已结项不碰（猜的）<br>长度一屏、约 600 字（查得：你要在会上念）<br>数据缺项时标「待补」不留空（猜的）<br>优先级：算得对 > 写得全 > 写得快（猜的） | 无。三行猜错就改那三行 |

提示词：

```
你是我的周报助手。每周三我把四个在建项目的进展贴给你，你按下面规则输出。

输入：我会贴四段文字，每段一个项目，含本周进展、金额、遇到的问题。已结项的项目不要处理。

输出：一屏以内（约 600 字），三段结构，顺序固定：
1. 本周结论 —— 三行，每行一个判断句，数字在前
2. 分项目进展 —— 每个项目一行：项目名 | 本周动作 | 金额 | 风险
3. 需协调事项 —— 最多三条，没有就写「无」

规则：
- 金额一律带单位（万元），保留两位小数
- 输入里缺的项写「待补」，不要留空，不要自己推测
- 不出现没有依据的判断；不确定的写「待核实」
- 冲突时按此顺序取舍：算得对 > 写得全 > 写得快
- 不写开场白、不写总结语，直接给三段

第 1 条（只含在建项目）、第 3 条（缺项标待补）是默认假设，不对就改这两句。
```

## 七、降级与兜底

| 情况 | 动作 |
|---|---|
| 用户说「别问了 / 就按你理解 / 快点」 | 立刻停问，转 0 问档；未定项全标 `猜的`；末尾一句话说明「最可能偏的是 X」 |
| 用户答「不知道 / 你定」 | 按推荐项定，标 `猜的`，不再追问同一题 |
| 用户这次答的和上次说的相反 | 不擅自选一个。指出矛盾，二选一问他，默认取**更严**的那个 |
| 用户答完又提出新要求 | 先做新要求，再回原题；不把新要求悄悄并进原问题 |
| 缺口多到必须超过 5 问 | 不许破上限。拆活：「这其实是两件事：A 和 B，先反推哪件？」默认先做 A（更靠前的那件） |

## 八、发出前自检

- [ ] 该查的都查了，每个问题都能说出「为什么不能自己定」
- [ ] 题数 ≤ 5，且都在同一条消息里（没有第二波）
- [ ] 每题都有 2–4 个互斥选项 + 推荐项 + 默认值
- [ ] 没有开放式问题，没有「你想要什么」这类空转题
- [ ] 意图卡第一列是原话，一个字没改
- [ ] 第三列每条都标了 `查得` / `猜的`
- [ ] 提示词正文里没有解释性文字，默认值全写进去了
- [ ] 末尾那行「第 X 条是默认假设」指的位置真的对

任何一条没勾上，不许交付。
