# 改前改后案例（简体中文）

每条案例标注改了什么，以及**哪些东西刻意没动**。

---

## 1. 汇报材料开头：删套话，数字不能跟着丢

**改前**
> 在快速变化的时代背景下，项目团队围绕提质增效开展了系统化实践。值得一提的是，本季度发布 3 个版本，修复了 17 个线上问题，进一步赋能了组织协同。

**改后**
> 团队本季度围绕提质增效开展了系统化实践，发布 3 个版本，修复 17 个线上问题。

**改了什么**：删"在快速变化的时代背景下"（A1 无证据拔高）、删"值得一提的是"（C7 填充句）、删"进一步赋能了组织协同"（A6 空泛行话，没有说清赋能了谁）。

**没动**："3 个版本""17 个线上问题""系统化实践"——这是原文自己的判断，保留。

---

## 2. 技术文档：不为口语化降格

**改前**
> 在长上下文推理中，latency 会随着 context window 的扩展而发生变化，因此我们不能仅仅使用单一的指标来判断系统的整体性能表现。

**改后**
> 长上下文推理的 latency 随 context window 扩展而变化，不能只用单一指标判断系统性能。

**改了什么**：删"在…中"前置状语（C1），"随着…的扩展而发生变化"改"随…扩展而变化"（C1 + C4 抽象名词化），删"我们"（无必要人称），"整体性能表现"改"系统性能"（D1）。

**没动**：latency、context window 保留英文原词（术语不动），因果成立，正式程度不变。

---

## 3. 公文：砍行话，保留责任关系

**改前**
> 各部门要聚焦薄弱环节，强化过程管控，压实主体责任，形成齐抓共管的工作闭环，切实推动各项任务落地见效。

**改后**
> 各部门要在 11 月底前完成薄弱环节整改，每周报一次进度，由分管领导签字确认。

**改了什么**：**这一条必须先把含糊的问清楚再改**。"薄弱环节"具体指什么、"过程管控"是什么动作、"主体责任"是谁——不知道就不要动，直接问。

上面这版改后的文字是**假定作者能提供具体内容**时的样子：动作、时限、责任人、验证方式都落地。如果作者说不清，正确做法不是编，而是标 `【需确认：薄弱环节具体指哪几项？】`。

**没动**：要求的强制性、责任层级。

---

## 4. 公众号：去对称骨架，留作者声口

**改前**
> 这不仅是一次产品升级，更是一次对用户习惯的重塑。它不是功能堆砌，而是对使用场景的深度理解。

**改后**
> 这次升级改了三个地方：搜索框移到了顶部，导出支持 Excel，历史记录能存一年。前两个是用户提了两年的，第三个没人提，但后台数据显示有 37% 的人在用。

**改了什么**：拆掉"不仅…更是…"（B2）和"不是…而是…"（B1），换成具体改了哪三处、谁提的、数据多少。

**没动**：作者的判断"这次升级值得说"。

**注意**：这里补的三个细节是案例虚构的。真实场景下**不能这样补**——原文没给细节，就必须问作者要，或者删掉那句空评，而不是编三个功能出来。

## 5. 真人文字：不要动

**原文**
> 我到楼下才想起来钥匙还在桌上。站了两秒，又觉得有点好笑——这周已经第二次了。

**处理**：不改。

有具体经历、自嘲、不规则的节奏、真实的停顿。硬改只会把它改成"我下楼后发现钥匙遗落在桌面上，这是本周第二次发生类似情况"——更"规范"，也更假。

## 6. PPT 单页：三栏并排改纵向

**改前（一页）**

标题：`以数字赋能促管理提升，以闭环管控固经营根基`

```
┌────────────┬────────────┬────────────┐
│ 一是构建统  │ 二是强化过  │ 三是沉淀方  │
│ 一指标底座，│ 程管控，建立│ 法论，输出标│
│ 贯通业务与  │ 周例会与月度│ 准化操作手册│
│ 财务口径…   │ 复盘机制…   │ ，推动经验… │
└────────────┴────────────┴────────────┘
下一步将持续深化系统应用，拓展覆盖范围，进一步赋能基层单位…
```

**问题**：三栏并排 + 下方纵向段落（方向混杂）、每栏四行（横向套纵向）、单页 169 字（超载）、标题对仗口号化（零事实）。

**改后（拆两页）**

第一页：
```
电气数据口径统一，月底出表从 5 天压到 1 天
──────────────────────────────────────
原来业务和财务各算一套，对不上就人工调，一个月吵三次
现在共用一套指标定义，差异当天能查到明细
下一步接成本口径，预计 11 月上线
```

第二页：
```
周例会跑了 8 个月，问题平均 6 天闭环
──────────────────────────────────────
上半年 47 个问题，43 个在两周内关掉
剩下 4 个都是跨部门的，卡在预算
```

**改了什么**：标题从口号改成判断句（带数字）；三栏内容按"数据口径""过程管控"拆成两页；每页纯纵向；每页 ≤60 字。

## 7. 打分验收的实际用法

改前跑一次，改后再跑一次，对比：

```
改前：65/100 偏重   命中 A1 A2 A4 A6 B1 B2 B3 B5 C1 C7 D1
改后：18/100 干净   命中 D1×2（"进一步""提升"，可接受）
```

**注意**：
- 分数到 0 不现实，也没有必要。真实材料里"提升""推动"这类词有时就是最准的说法
- 决定性模式（A1 A2 A4 A5 A6 B1 B4 E4 E5 E6）一个不留，是硬要求
- 分数降下来了但读起来更拗口 → 以读起来为准，说明改法机械了，回去重排结构
