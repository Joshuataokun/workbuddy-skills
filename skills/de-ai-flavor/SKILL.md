# 去 AI 味（简体中文）

把机器腔的中文改回人写的，同时保证改完还能拿去用——数字不漂、责任关系不丢、该正式的地方不降格。

**只做简体中文。** 不处理繁体、不做翻译、不从零代写。

## 0. 先判断要不要动手

动手前先问三件事，任何一件不清楚就不要改：

| 检查 | 不清楚时 |
|---|---|
| 这份文字给谁看、什么场合（汇报 / 公文 / 公众号 / 内部纪要） | 问一句。语体不同，改法完全相反 |
| 数字、责任主体、时间、引用能不能动 | 默认一律不动 |
| 是不是本人写的、只是想让读起来顺 | 是 → 只做轻度处理，不改结构和观点 |

**遇到下面情况停手，直接告诉用户：**

- 文本明显是人写的（有具体经历、自嘲、不规则节奏、真实犹豫）→ 不改，说明理由
- 只有一句 "帮我看看"、没提任何改写要求 → 先问要往哪个方向改
- 原文事实互相矛盾，或数字前后不一致 → 标出来问，不替作者选一个
- 出现疑似密码、密钥、身份证号 → 停，要求先脱敏

## 1. 五步流程

1. **立事实账本**：先把数字、日期、人名、单位、条款、结论强度抄成一张清单。
2. **定语体**：公文/汇报/技术文档/公众号/内部纪要，五类各自的底线不同（见 §3 各族的「保护」）。
3. **扫症状**：按 §3 的 A–E 五族过一遍，再看 §4（PPT）或 §5（验收）。
4. **重排而不是替换**：先动句子结构和信息顺序，词表替换放最后。只换词不改结构，改完还是机器腔。
5. **回读三查**：数字有没有漂 → 责任关系有没有变 → 结论强度有没有被抬高或削弱。

## 2. 红线

改完必须成立：

- **数字、比例、金额、日期、编号**：一个字不动
- **谁做的、向谁报、谁批的**：不动，不把"参与"写成"负责"，不把"相关"写成"因果"
- **引用与出处**：引文跟着被支持的句子一起移动，不单独搬
- **结论强度**："体现了流程优化" 不能改成 "优化了流程"
- **正式程度**：公文、技术文档不因为"去 AI 味"降成聊天口吻
- **专用名词**：术语、法定全称、机构名不为了"口语化"拆掉

改完发现做不到上面任何一条 → 停在这一句，标 `【需确认】` 问作者，不要自己补。

**唯一的例外：标点、空格、不可见字符（见 E-2）。** 这几类属于格式层，直接改，不必逐条确认——它不改变任何一个字词和判断。改完在交付里说明改了哪几类就行。

## 3. 文字症状（五族）

每条按「骨架 / 触发 / 保护 / 动作 / 复扫」用。命中多条相邻的只处理一次。

### A 内容真实性与具体性

**A1 无证据拔高**
- 骨架：由普通事实跳到里程碑、时代转折、战略意义。`标志着` `里程碑` `新篇章` `具有重要/深远意义` `为…提供有力支撑` `奠定坚实基础`
- 触发：评价超出原文事实能撑住的范围，或纯粹在造气势
- 保护：作者自己下的评价属于原意，保留，只改承载方式（事实在前，评价另起一句）
- 动作：先写事实，再写评价；纯空升删掉
- 复扫：结尾有没有又把局部事件推到宏大尺度

**A2 模糊归因**
- 骨架：`业内人士` `研究表明` `专家指出` `普遍认为` `众所周知` `有关方面`
- 触发：没有出处，或出处撑不起这个范围
- 保护：真实来源、完整调查范围
- 动作：能具体到就具体到（谁、哪一年、什么报告）；具体不了就标待核，不要留着冒充权威
- 复扫：全文所有归因能不能指回一个可查的东西

**A3 泛化无细节**
- 骨架：`相关领域` `广泛关注` `某种意义` `各类场景` `在一定程度上` `存在一定联系`
- 触发：抽象词把原文本来有的具体信息盖掉了
- 保护：原文确实只给范围时，不补造细节，也不因为模糊就删掉这个判断
- 动作：还原原文已有的人、事、时间、条件
- 复扫：有没有把"参与"改成"负责"、把"相关"改成"因果"

**A4 假平衡与未来可期**
- 骨架：`尽管面临…挑战，但未来可期` `既要…又要` `一方面…另一方面`
- 触发：没有真实冲突、条件或决策，只是把句子缝回积极方向
- 保护：原文确有权衡、计划、态度
- 动作：写清条件和决策；无信息的乐观收尾直接删
- 复扫：每段结尾是不是都被统一缝回正面

**A5 空转收尾**
- 骨架：`总之` 复述全文，再 `迈上新台阶` `续写新篇章` `必将实现` `让我们共同…`
- 触发：结尾没有新结论、新决定、下一步
- 保护：正式摘要、结语章节、用户明确要求的行动项
- 动作：停在最后一个有信息的事实、判断或动作上
- 复扫：段尾和全文结尾有没有重复前文

**A6 空泛行话**
- 骨架：`赋能` `抓手` `闭环` `底座` `打通` `沉淀` `对齐` `提质增效` `顶层设计` `颗粒度` `组合拳`
- 触发：密集出现，却没有说清谁做了什么、做出了什么
- 保护：行业固定用语、原文有明确对象的用法
- 动作：换成"谁 + 做了什么 + 结果"；一行里两个以上就必改
- 复扫：删掉这些词以后句子是否还有信息

### B 修辞骨架

**B1 不是 X，而是 Y**
- 骨架：`不是…而是` `并非…而是` `不在于…而在于` `与其说…不如说`
- 触发：两端抽象、对称，或只把概念换个名字；去 AI 味时，显眼的骨架即使出现一次也可以重写
- 保护：真实引用、固定定义、事实纠错、范围排除
- 动作：冻结两端含义，改成事实主干、独立句或条件句
- 复扫：换成"问题不只在…" "涉及的却是…" 仍算残留，换词不算改

**B2 不仅 X，更 Y**
- 骨架：`不仅…更/还/也…`
- 触发：两端都在给同一件事加码
- 保护：两端确有信息递进
- 动作：保留信息多的一端，另一并进同一句

**B3 从 X 到 Y**
- 骨架：`从…到…再到` `从…走向/迈向/跃向…`
- 触发：X 和 Y 不在同一个尺度上，只是听着有气势
- 保护：真实时间跨度、真实范围
- 动作：改成具体时间、具体范围，或直接列事实

**B4 假揭示**
- 骨架：`看似…实则…` `表面…背后…` `真正的…是…` `这背后的逻辑是`
- 触发：两端只是两个抽象评价，中间没有事实建立层次
- 保护：作者真的在纠正一个流行误读
- 动作：让事实先建立关系，再直接写结论；不要用"其实/真正"换个壳继续造揭示感

**B5 序数骨架**
- 骨架：`首先/其次/再次/最后` `第一/第二/第三`
- 触发：个人叙述或短段落被硬拆成整齐几点，而内容并不需要顺序
- 保护：操作步骤、责任分工、答题结构、真实分类
- 动作：合并成自然段，或改成真正的层级（一级标题 + 项）

**B6 连接词链**
- 骨架：段段以 `然而` `此外` `因此` `同时` `总之` 开头
- 触发：连接词增多而信息和证据没有推进
- 保护：真实因果、转折、补充
- 动作：删掉多余连接词，让句子自己接住

**B7 破折号连缀**
- 骨架：一个句子里两个以上 `——` 或 `—`
- 触发：靠标点制造停顿和气势，而不是靠句法
- 保护：对话中断、真实停顿、术语解释
- 动作：先重写句法，再决定要不要留一个

### C 句法语序（中文特有，最常见）

**C1 前置状语堆叠 / 主干后置**
- 骨架：`在…背景下` `随着…` `基于…` `围绕…` 一句叠两句，谓语到第五十字才出现
- 触发：读者要回头找"谁做了什么"
- 保护：法律、公文、技术定义里承担适用范围的前置条件
- 动作：先立主干（谁 + 动作 + 对象），再把时间、条件、范围放到动作附近
- 复扫：每句能不能一眼指出行动者、动作、对象

**C2 翻译式被动**
- 骨架：`被…所…` `被…进行…` `被…予以…` 连续出现
- 触发：被动没有明确受事，只是逐词翻译的痕迹
- 保护：被动能明确受事或责任的句子
- 动作：能明确施事就改主动；确实不知道谁做，保留被动但删掉"所/进行/予以"

**C3 定语链过长**
- 骨架：一句话里连续三个以上"…的"
- 触发：名词前的修饰把一个从句塞进定语
- 保护：术语全称、法定名称
- 动作：拆成两三个短句，或把定语提成小标题

**C4 抽象名词化**
- 骨架：`进行/实现/推动/构建/开展/加强 + 抽象名词`（进行管理、实现提升、推动落实）
- 触发：行动者和动作被埋进名词里
- 保护：学术、公文、法律、技术里的稳定术语
- 动作：恢复"谁做了什么"；不要机械拆术语
- 复扫：段落主干是不是还由抽象名词撑着

**C5 性化堆叠**
- 骨架：`系统性` `整体性` `协同性` `精准化` `规范化` 连续出现
- 触发：一个名词身上挂两个以上"性/化"，而没有一个能落成具体动作
- 保护：术语本身带"性/化"的固定说法
- 动作：留一个最准确的，其余删；或换成能验证的做法

**C6 限定词串联**
- 骨架：`可能/或许/一定程度上/相对/基本上` 叠加
- 触发：多个限定表达同一种不确定
- 保护：证据等级、适用范围、风险披露
- 动作：留最准确的一个；不能把不确定清洗成肯定

**C7 填充句**
- 骨架：`值得注意的是` `需要指出的是` `不可否认` `显而易见` `换言之` `在此基础上` `为了更好地`
- 触发：删掉之后信息一点没少
- 保护：真实的风险提示、必要的转场
- 动作：删

### D 词汇

**D1 AI 高频词**
- 骨架：`赋能 助力 打造 构建 深化 推动 强化 优化 提升 聚焦 锚定 对标 贯通 全方位 多维度 深层次 精准 高效 扎实 有力 有序 稳步 持续 不断 进一步 切实 着力 突出 彰显 新高度 新格局`
- 触发：每千字超过约 12 次，或一行内两个以上
- 保护：法规原文、上级文件原话、专业定义
- 动作：换成具体动作词或直接删；同一个词一段内不重复
- 复扫：换完之后有没有为了避词造出更生硬的搭配

**D2 同义反复**
- 骨架：相邻句重复同一名词/动词，或换同义词把结论重说一遍
- 触发：重复不承担强调、消歧作用
- 保护：关键术语、法定全称、避免歧义的点名
- 动作：合并句子，省略已知主语

**D3 生硬搭配**
- 骨架：`接住观点` `击穿思考` `托住情绪` `拉齐水位` 这类动作词挂在没有对应关系的对象上
- 触发：能逐字倒译回英文，中文里没有这个搭配习惯
- 保护：真实动作、行业惯用语、人物原话
- 动作：换回普通动词，或直接写结果
- 复扫：不要为了口语化制造另一种生硬

### E 格式残留

**E1 粗体装饰**：正文里 `**关键词**` 一个段落出现两个以上 → 去掉粗体，让句子自己承担重点
**E2 行内标题列表**：每条都是 `**标签：**解释` → 改散文，或改成真正的分项（标题归标题）
**E3 表情符号**：标题、要点前的 emoji → 全删
**E4 聊天残留**：`希望以上对你有帮助` `如需进一步` `以下是关于…` `当然可以` → 删
**E5 知识截止声明**：`截至我的知识更新` `根据现有信息` `由于资料有限` → 删，改成待核标记
**E6 占位符未填**：`[姓名]` `XX` `待补充` `TBD` → 列出来问，不代填
**E7 引号方向**：中文正文该用中文引号 `""` 或 `「」`；中文里出现英文直引号 `"…"` 属于格式残留 → 换成中文引号。**注意：不要做反向操作**，把中文引号改成英文直引号是错的。

### E-2 标点与空白（改动最小、见效最快）

这一类跟文字表达无关，是**字符形式**的问题。真人打中文用输入法，标点天生是全角，几乎不会错；AI 输出中文时沿用英文语料的半角习惯，破折号也从英文 em dash 继承下来。所以这类错误出现得越密集，越说明这段文字不是人敲的。

**好处是改它零风险**：不动一个字词、不动一个判断、不动一处数字。

| 编号 | 错误 | 应为 | 说明 |
|---|---|---|---|
| E8 | 汉字之间夹 `,` `;` `:` `?` `!` | `，；：？！` | 中文正文一律全角 |
| E8 | 汉字之间用 `.` 收句 | `。` | 数字 `3.5`、小数、版本号不算 |
| E9 | `...` 或 `。。。` | `……` | 省略号占两个字宽，共六个点 |
| E9b | `--` 或单个 `—` 或 `–` | `——` | 破折号占两个字宽，两个 em dash |
| E10 | 汉字与汉字之间夹空格 | 删掉 | 见下条保护条件 |
| E11 | 全角标点前后多一个空格 | 删掉 | 全角标点自带视觉宽度，加空格会裂开 |
| E12 | 不换行空格 U+00A0、零宽字符 U+200B–200D、BOM U+FEFF | 换成普通空格或删除 | 从网页、AI 对话框复制时带进来的 |
| E12 | 句中夹全角空格 U+3000 | 改成普通空格或删 | 段首缩进用的不算 |
| — | `·` 当顿号用 | `、` | 间隔号只用于译名（马克·吐温）、书名篇名分隔。**脚本暂不检，靠眼看** |
| — | `~` `～` 表示范围 | `至` 或 `—` | 「3~5 天」→「3 至 5 天」。**脚本暂不检，靠眼看** |

**保护条件：下面这些位置保留半角，一个字都不许动。**

- 代码、变量名、函数调用、命令行：`foo(x, y)`、`git push`、`--force`
- URL、文件路径、邮箱：`https://example.com/path?q=1`、`C:\Users\`、`a@b.com`
- 版本号、数字、单位、比较：`v1.0.0`、`30%`、`2.5 小时`、`< 200 字`
- 行内英文短语内部：`hello, world`
- Markdown 列表编号：`1.` `2.` `3.` 仍是半角
- **中文排版规范要求保留的空格**：`图 1`、`表 2`、`第 3 章`、`3 个版本`——数字与中文之间的空格是规范做法，不是 AI 味
- 直接引用法规、合同、英文原文的段落：照原样，不改

**判断口诀**：错的是「汉字挨着半角标点」和「汉字挨着汉字还有空格」。数字、字母、代码周围不碰。

**与 `chinese-punctuation-fixer` 的分工**：那个技能负责批量修复 txt 小说的引号配对和全半角，产出新文件；本技能只判断「这算不算 AI 味」并给改法，不替代它的批量修复流水线。同一份稿子两边都过，先跑它修字符，再用本技能看还剩多少味。

## 4. PPT / 汇报版面：一页只能有一个阅读方向

汇报是线性的。观众跟着讲者一句话一句话走，视线不回头。所以判断一页有没有 AI 味，先不看配色，看**这一页要求观众怎么读**。

### 4.1 核心判据：视线不许转弯

一页里如果同时存在两条通路——一条从左往右（并排的几栏），一条从上往下（段落推进）——观众就得先选一条，注意力当场散掉。这就是"乱"的来源。

**三种合法版式，一页只能用一种：**

| 版式 | 结构 | 什么时候用 |
|---|---|---|
| 纯纵向 | 标题 → 一句判断 → 2–3 段短支撑，全部左对齐，一条竖线下来 | 默认。几乎所有内容页 |
| 纯横向 | 一条轴上并列若干单元，**每个单元只有一行字** | 真正同质并列：时间轴、阶段、三个指标、几个分厂对比 |
| 主纵向 + 右侧注释栏 | 左边正文推进，右边一列只放数字、来源、图例 | 右侧必须是注释，不能是第二列正文 |

**必须改掉的四种版面：**

1. **三栏卡片并排，下方再压一段正文** —— 同页两种方向，最典型的 AI 版式
2. **三栏并排，每栏两行以上** —— 横向里又套了纵向，观众横着扫完还得竖着读
3. **左右两栏都是正文** —— 没有主次，观众不知道先读哪边
4. **上中下三层、每层左右再分** —— 网格化，等于要求观众走迷宫

### 4.2 一页一个结论

- 标题必须是**能念出口的判断句**：主语 + 动作 + 结果，带数字更好。`电气类停机占非计划停机的 39%`
- 不要口号式、对仗式标题：`以数字赋能促管理提升，以闭环管控固经营根基` → 这句听起来顺，但观众记不住任何一个事实
- 一页只讲一件事。看到"一是…二是…三是…"并列在同一页，先问：这三件事是不是同一层级的动作？不是就分页

### 4.3 字数与节奏

- 单页正文 ≤120 字，硬上限 150。超了就把细节赶进备注或附录
- 每页要点 ≤5 条，最好 ≤3 条
- 相邻页的元素数量要有变化：连续三页都是"1 个标题 + 3 个框"，观众会以为在翻同一页
- 数据页必须有来源和口径；没有就标"待补来源"，不要放一个没有出处的数字

### 4.4 改版动作顺序

1. 先把这一页要说的那句话写下来（一句话，不许两句）
2. 决定方向：纵向还是横向。只能用一种
3. 删掉所有不支撑那句话的元素
4. 剩下的元素按方向排：纵向就一路左对齐往下；横向就只留一行字
5. 最后才调字号、留白、配色

### 4.5 别做的美化

渐变紫蓝底、圆角卡片堆叠、bento 网格、图标雨、无意义大数字、3D 玻璃球、发光描边——这些不是"设计感"，是把观众的注意力从内容上引开。工业、工程、政务类汇报尤其不要用。

## 5. 量化验收

技能自带离线检测器，零依赖（Python 3.9+），不联网，不调模型。

```bash
# 文字
python scripts/deai_check.py 稿子.md
python scripts/deai_check.py 稿子.docx        # 直接读 docx，不改变原文件

# 汇报材料（文字 + 版式双通道）
python scripts/deai_check.py 汇报.pptx

# 机器可读
python scripts/deai_check.py 稿子.txt --json

# 自定义上报阈值（默认 40），超阈值退出码 1
python scripts/deai_check.py 稿子.txt --min 30
```

输出内容：0–100 分、五档结论（干净 ≤20 / 轻微 ≤40 / 明显 ≤60 / 偏重 ≤80 / 重度）、命中模式编号与样例、句长变异、段长变异、AI 词密度；PPT 另出版式评分与逐页问题。

### 怎么用这个分数

- **不是判作者，是判稿子。** 分数高说明写法像机器，不说明是人写的还是 AI 写的，不能拿去指认谁
- **先看命中项，再看分数。** 分数是汇总，改哪一句要看命中了哪条
- **改完重跑一次**，低于 40 再交；交付前追求 ≤20 不现实，也容易把文字改僵
- **短文本（<120 字）结论不可靠**，脚本会自己标"样本不足"
- **扫教学材料、规范文档、案例库会命中一堆**——它分不清「这里是反面例子」还是「这里是正文」。这类文件看命中位置对不对，别总分

### 改完的验收标准

| 项 | 通过线 |
|---|---|
| 文字总分 | ≤40（重要材料 ≤30） |
| 决定性模式（A1 A2 A4 A5 A6 B1 B4 E4 E5 E6） | 一个不留 |
| **标点与空白（E8–E12）** | **一个不留——这几条是硬伤，与分数无关，命中就要改** |
| 数字、责任、引用 | 与原文逐条核对一致 |
| PPT 版式 | 没有"并排 + 纵向同页"，没有单页超 150 字，没有口号式标题 |

## 6. 输出格式

**默认（用户贴了文字）**：给三段——改后正文、改了什么（按编号列）、仍需作者确认的地方。

**只给终稿**（用户说"只要终稿/直接给改好的"）：只输出正文，不解释。但红线不放宽，该标 `【需确认】` 的照样标。

**文件模式**（用户给了路径）：改完写回文件或另存，代码块、路径、命令、YAML 一律不碰。

**PPT 模式**：先出一张逐页问题表（页码 / 问题类型 / 改法），用户确认后再动版面。不要未经确认就重排。

## 7. 来源与边界

- 中文症状目录参考 [qu-ai-wei](https://github.com/LifelongLazyLearner/qu-ai-wei)（MIT），证据等级与「骨架/触发/保护/动作/复扫」结构沿用其方法；E-2 的全半角对照与例外清单亦参考该项目。
- 标点形式以国家标准 **GB/T 15834—2011《标点符号用法》** 为准（破折号、省略号各占两个字宽；间隔号占半个字宽）。
- 英文侧原始方法参考 [blader/humanizer](https://github.com/blader/humanizer)（MIT）与维基百科《Signs of AI writing》。本技能已改为纯简体中文规则，英文规则不再适用。
- 打分架构、Office 文件抽取逻辑移植自 [sloptrim](https://github.com/seyedehsanhadi/sloptrim)（Apache-2.0），规则库为中文重写。许可证见 `NOTICE-sloptrim.md`。
- **这个技能不判断作者身份。** 它只描述文字和版面哪里像机器，不构成对人的判断，也不能用于指控。
- 不协助规避学校、期刊、单位的 AI 使用规定。
