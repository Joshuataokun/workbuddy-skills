# 分册拆分口径与条目标记规范

## 一、主卡七段

| # | 段名 | 放什么 | 不放什么 |
|---|---|---|---|
| 1 | 项目目标 | 一句话交付物 + 验收对象 | “提升效率”这类空话 |
| 2 | 口径与约束 | 跨工作面都成立的硬规则：发布方式、版本号规则、合规红线 | 单个子项目的接口细节 |
| 3 | 已排除方案 | 被否掉的方案 **+ 否决原因** | 只是“没做”的 |
| 4 | 已完成 | 已发生的事实，带日期 | 计划中的事 |
| 5 | 当前进度 | 现在在哪、下一步做什么 | 长篇过程 |
| 6 | 待确认 | 用户没拍板的问题 | 自己推测的结论 |
| 7 | 关键位置 | 工作区根 + 分册指针 | 细节清单（进分册） |

## 二、分册五段

| # | 段名 | 放什么 |
|---|---|---|
| 1 | 职责与范围 | 这个工作面负责什么，边界在哪 |
| 2 | 口径与约束 | 只对这个工作面成立的规则、命令、预算 |
| 3 | 已完成 | 已发生的事实 |
| 4 | 待办 | 明确的下一步 |
| 5 | 关键位置 | 文件路径、入口、脚本清单 |

**拆分口诀**：换一个工作面就说不通 → 进分册；放哪儿都成立 → 留主卡。
**分册过一屏就该再拆。**

## 三、条目标记

```
- 【确认·YYYY-MM-DD·"用户原话"】条目正文
- 【待确认】条目正文
```

| 写法 | 判定 | 原因 |
|---|---|---|
| `- 【确认·2026-10-25·"内网部署"】部署在内网` | 通过 | 有日期有出处 |
| `- 部署在内网` | 拒绝 F03 | 无标记，无法追溯 |
| `- 【确认·2026-10-25】端口应该是 8080` | 拒绝 F04 | 推测词 + 标确认 |
| `- 【待确认】端口可能是 8080` | 通过 | 诚实标注 |
| `- 【确认·2026-10-25】数据库密码: Abcd1234` | 拒绝 F05 | 明文凭据 |
| `- 【待确认】未来日期 2030-01-01` | 拒绝 F10 | 未来日期 |

## 四、拒绝码

| 码 | 触发 | 处理 |
|---|---|---|
| F03 | 缺日期或标记 | 拒绝，文件不动 |
| F04 | 确认项含推测词 | 拒绝，改成 --pending |
| F05 | 明文凭据 | 拒绝，改记“凭据在哪” |
| F09 | 覆盖已存在的卡/分册 | 拒绝，除非 --force |
| F10 | 未来日期 | 拒绝 |

推断词表：应该、可能是、大概、估计、也许是、我猜、猜测、或许是、看上去像、八成、感觉是、大概率。

## 五、更新时机

| 时机 | 写到哪 |
|---|---|
| 一件事做完 | 主卡 `已完成` 或对应分册 `已完成` |
| 定了新规则／推翻旧规则 | 主卡 `口径`（旧的删掉），专属的进分册 |
| 方案被否 | 主卡 `已排除方案` + 原因 |
| 冒出新问题 | `--pending` 进 `待确认` / 分册 `待办` |

不必更新：纯技术问答、查资料、没产生决定的闲聊。
