# 中文标点修复大师（Chinese Punctuation Fixer）

## 概述

一站式修复 txt 小说/中文文本的标点符号问题。核心资产是经过真实小说
（约 1.2 万行）验证的脚本流水线，覆盖从「英文格式符号转中文格式」到
「引号配对修复」的全链路，具备幂等性（重复执行不再产生改动）与完善的
白名单保护（URL/邮箱/小数/时间/纯英文/嵌套强调/风格化延长音）。

## 何时使用

- 用户要求修正、校对、整理小说或中文文本的标点符号
- 引号不匹配、配对错误、开闭颠倒、漏写
- 英文格式标点（直引号 "..."、半角 , . ! ? : ;）需要转成中文格式
- 省略号、破折号、波浪线等特殊符号写法不规范
- 全角字母数字（ＡＢＣ１２３）混入文本

## 标准流程

### 第一步：检查（可选但推荐）

```bash
python scripts/fix_punctuation.py "输入.txt" --check
```
只生成报告不写文件：统计各类问题数量、引号平衡情况、需人工关注的位置
（未配对引号、行首标点禁则）。适合先评估工作量再决定是否修复。

### 第二步：执行修复

```bash
python scripts/fix_punctuation.py "输入.txt" "输出.txt"
```
缺省输出为「原名_已修正标点.txt」，不覆盖原文件。保留原文件的
BOM 与换行符风格（CRLF/LF）。

### 第三步：验证与交付

脚本自动打印修复报告。确认「左右引号平衡、差为 0」后，向用户报告
修改处数与错误类型分布，并通过 present_files 交付新文件。

**报告差不为 0 是正常的**——重度 OCR/AI 稿一定有机器不敢判断的行
（整句重复、冒号后写反、译本残句）。这时候正确做法是：

1. 跑一次幂等校验（输出再喂一遍，第二次必须零改动；看输出是否相同，
   不要看报告合计，见注意事项 16）；
2. 校验正文完整性（去掉标点后与原文逐字比对，字数必须完全一致）；
3. **另出一份「需人工复核」清单**：列出仍不平衡的行号 + 原文，让人
   直接在上面改。清单格式固定为 `[第N行] 左x 右y` + 该行原文，用户
   改完可以回收成语料，反推下一条规则（2026-10 的 D1–D7 就是这么来的）。
4. **顺手读两段「仅报告」区块**：脚本还会输出「成对标点检查」（书名号/
   括号不配对的行号）和「引号内句末标点 · 仅报告」两段。这两段**刻意
   不改正文**，原因见注意事项 17–19：一个改动可能删内容，一个补/删/
   移都说得通。把它们当人工清单用，不要期待脚本替你决定。

### 行首标点禁则处理规则（用户确认过的决策）

- **续行合并**：行首是 `，！？；：、）】》」』` 或「破折号+正文」时，
  与上一行合并（明显是一句话被换行拆断）。上一行是空行/章节标题/
  分隔线时不合并；整行只有 `——` 是独立中断标记，不动。
- **闭引号开头也是续行**：`”`/`’` 开头的行是上一行被拆断的引语，
  同样合并（`_MERGE_LEAD` 已含闭引号）。
- **行首句号删除**：句号开头明显不对，删除；删后整行空了就连行删除。
  例外：`。”` 这种句号后紧跟闭引号的，是上一行被拆断的句尾，改为合并。
- **省略号开头保留**：可能是作者刻意留白/分隔，不动（列入报告供人工判断）。
- **开引号 `“` 开头**：是新对话开头，正常排版，不算禁则。

### 单引号层级提升（GB/T 15834-2011 外双内单）

国标规定引号嵌套时外层用双引号、内层用单引号。但很多作者把单引号
当对话引号或着重引号用（`'你好'` 应为 `"你好"`）。规则：

| 情形 | 处理 |
|------|------|
| 双引号深度**之外**的 `' '` | 提升为 `""`（它不可能是合法嵌套） |
| 双引号深度**之内**的 `' '` | 合法嵌套，保留 |
| 两个 ASCII 字母/数字之间的 `'`（don't） | 撇号，保留 |

深度状态机：`“` +1 / `”` -1（不低于 0）。单引号提升会改变双引号
布局，与配对修复、行首合并互相影响，因此三者在不**动点循环**中
迭代到一次完整迭代零改动（见注意事项 7）。

### 空引号对修复（`“”`）

双引号之间没有内容即为空引号对。两大来源：① 作者倒置引号习惯
（开引号写 `”`、闭引号写 `“`）与配对补引号叠加；② 作者原文自带的
包裹残骸。规则（逐行按序，全部要求真实存在 `“”`，故不会误伤
干净文本）：

| 规则 | 模式 | 说明 |
|------|------|------|
| E1 包裹空对 | `“”X“”` → `“X”` | 整行包裹的对话/强调 |
| E2 行首空对 | `^“”` → `“` | 行首多余的开引号 |
| E3 倒置对话对 | `[：，]”X“”` → `[：，]“X”` | 冒号/逗号后倒置的对话对 |
| E4 短强调倒置对 | `”X“”` → `“X”` | X≤10字且无句读（排除正常闭引号+新引语） |
| E3/E4 附带补闭 | 翻转后行内首个开引号未闭合时，在其后、下一个引号之前的最后一个 `。！？…` 后补 `”` | 作者对话开了头没结尾的常见缺陷 |
| E5 行尾移动 | `”X“”$` → `”“X”` | X 含 `……！？`：上一闭引号正常、X 是漏引言语（旁白无标记，交 E6 删除） |
| E6 行尾残骸 | `X“”$` → `X` | 其余行尾空对直接删除（不猜语义） |
| E7 冒号言语 | `：X“”` → `：“X”` | 冒号后漏引言语+空对 |
| E8 整行强调 | `A“”B“C”$` → `A“B”C` | A 非空：强调对前半边丢失 |
| E9 行首 debris | 行首 `“`+解说语（含言语动词+`：，`）+`“` → 删行首引号 | 仅奇数引号行（偶次是真嵌套，受保护） |
| E10 行首 debris（整行型） | `“`+长解说(≥10字)+`“言语”$ → 删行首引号 | 排除短嵌套残引 |
| E11 倒置强调对+的 | `”X“的` → `“X”的` | X≤10字无句读（「的」=定语信号：「啪、啪的声音」必强调） |
| E12 旁白开引号残骸 | `”“X“Y”` → `”X“Y”` | 紧邻对中的旁白开引号 |
| E12b 行首旁白残骸 | `^“X“Y”` → `X“Y”` | Y 短强调；真嵌套行保护 |
| E13 漏引言语 | `”X“` → `”“X”` | X 感叹词开头+情绪标记；`“`后30字内无闭引号才动 |
| E14 行尾多余闭引号 | 行尾 `”`（前有句读）且右>左 → 删除 | 旁白残骸，只在改善平衡时动手 |
| E15 行首 debris+倒置开引号 | `“解说[：，]”言语$` → `解说[：，]“言语` | 交替重排曾把第二个 `“` 错翻成 `”`（产生 `：”`） |

### 智能交替重排（fix_alternate）

纯位置交替（第 1、3、5 个=左，第 2、4、6 个=右）在多段漏闭言语并存
的行会按奇偶位误翻正常开引号（如 `道：“` → `道：”`）。智能版逐引号
从左到右、期望方向从「左」开始交替，并加两条保护：

1. **钉住言语引出开引号**：`“` 紧跟 `：`/`，` 之后 = 言语引出，保留不翻
2. **期望闭引号时遇到 `“`**：若行内其后还有闭引号 → 上一段言语漏写
   闭引号，此 `“` 是新开引号（保留，继续期望闭）；否则是倒置闭引号
   （翻正为 `”`）

实测（《覆雨翻云》）：`：”` 从 21+ 降至 **0**，多段漏闭行（如
`道：“蜿儿……道：“下次……“扑味”`）的开引号全部正确保留。

### 跨行倒置对话修复

作者的倒置引号习惯跨行出现：行N末尾 `”` 是倒置开引号（言语动词+
`：，`之后），行N+1首个 `“` 是倒置闭引号。例：

```
“秦柔侧着臻首，露出一个顽皮的笑容，模样可爱之极，柔声道：”
你还想怎么样？“
```

修复（`fix_crossline_inverted_quotes`）：删行N的 debris `“`（若有）、
行N末尾 `”`→`“`、行N+1首个 `“`→`”`，两行**合并**：

```
秦柔侧着臻首，露出一个顽皮的笑容，模样可爱之极，柔声道：“你还想怎么样？”
```

**为什么合并**：行N末尾的孤立开引号若保留，配对修复会在行尾补 `”`
生成 `“”` 空对（且跨行引号对会让逐行平衡/未闭合报告产生假阳性）。
合并成行内引号对后天然稳定。

**防误伤**：行N要求「引号仅出现在动词+`：，`+`”`之后」（行内含其他
引号不匹配）；行N+1要求「`“`前为无引号正文」（`“`直接开头是正常
对话，不匹配）。

### 断链引号修复（D1–D7，2026-10 新增）

**适用文本**：OCR 稿、AI 改写稿、盗版站转载稿。这类稿子的病根不是
零散错引号，而是**成系统的两种习惯**：

1. 闭引号一律敲成开引号（`。“` `， “` `！”` 混用）
2. 对话开头的开引号被吃掉（直接以对话正文起句）

两种习惯**相邻出现**时，逐行交替重排会被前一个病态带偏，于是「放弃整行」
或「按奇偶位误翻」，留下大量”看起来像嵌套、其实断链”的行。实测一本
4 万行 200 万字的小说：交替重排做完仍有 242 行不平衡、净差 273 个引号，
人工核对 35 例后补出本组规则，降到 46 行、净差 71。

**核心机制：预算法。** `budget = 行内 “ 数 − ” 数`，每把一处 `“` 翻正为
`”` 消耗 2 个预算（L−1、R+1）。因此：

- 已平衡的行（`L == R`）**根本不进规则**——合法嵌套强调 `“外“内”外”`
  天然免疫，不需要额外的嵌套判别；
- 只有「左引号确实过多」时才动手，永远不会把平衡行弄坏；
- 幂等：一行修平后预算为 0，再次执行零改动（实测二次运行 0 处改动）。

| 规则 | 模式 | 触发条件 |
|------|------|---------|
| D1 行首叠引 | `^““X` → `“X` | 行首多敲一个开引号 |
| D6 行尾孤立引 | `X。！“` → `X。！` | 行尾多敲的开引号残骸，前面紧跟句读或 `”` |
| D2 倒置强调对 | `“X“` → `“X”` | X≤10 字、**不含任何句读**、且该 `“` 处于引号深度 ≥1 |
| D3 倒置闭引号 | `。！“` → `。！”` | 紧跟 `。！？…`、非行尾、**深度 ≥1** |
| D5 补闭引号 | 行尾 `。` → `。”` | 余额恰为 1，且**最后一个引号是对话开场**（在行首或紧跟句读） |
| D4 补开引号 | `X，“旁白，“Y` → `“X，”旁白，“Y` | 行首漏开引号（见下方四条必要条件），同时把中间那个倒置闭引号翻正 |
| D7 补开引号 | `X？…”旁白` → `“X？”旁白` | 余额恰为 1、行首非 `“`、首个 `”` 之前无引号且不含句号、该段以 `？！…` 收尾 |

**D4 的四条必要条件**（少一条就会把「旁白＋对话」误当「对话＋旁白」，
实测漏掉任意一条都会在真实稿件上误伤几十行）：

1. 行内第一个 `“` 紧跟句读（`。！？…，`）
2. 该 `“` 之前的正文里**没有句号**「。」——句号是旁白收尾的信号；
   问号感叹号则常是对话自己的收尾（`九十分可以吗？老师？`）
3. 该 `“` 之前不含引号，且末尾 8 字内没有言语动词（`说道问答喊叫嚷骂笑叹`
   ——`…他说，“…”` 是旁白引出对话，不能补开引号）
4. 该 `“` 之后紧跟「旁白＋下一段引语」，旁白 ≥4 字（排除行尾残句）

**执行顺序（不可随意调换）**：D1 → D6 → D2/D3（合并取最左）→ D5 → D4 → D7。

- D6 必须在 D2/D3 前：行尾孤立开引号不先删掉，会被后续补闭规则配成
  `“…”`，把整段旁白包进引号（实测误伤过 20 行）。
- D2 与 D3 **合并取最左位置**：`…了。“她特意加重了“敬重”二字` 里
  「。后的引号」和「夹在两个引号之间的短词」形状都像倒置强调对，
  只有最靠左的那个才是真正的倒置闭引号。
- D5 必须在 D4 前：行尾就是缺一个闭引号时直接补；先补开引号会把
  「旁白＋新对话」读成「对话＋旁白」。

### 引号内句末标点归位（P1，2026-10 新增）

依据 GB/T 15834-2011：完整引用整句时，句末点号在**引号之内**。

| 情形 | 处理 |
|------|------|
| `他说：“我走了”。` | → `他说：“我走了。”`（句号搬进引号内） |
| `她问：“几点回来”？` | → `她问：“几点回来？”` |
| `他说：“我走了！”。` | → `他说：“我走了！”`（引号内已有句末标点，删外部重复） |
| `“我……”。` | → `“我……”`（省略号已表结束，删外部句号） |
| `他说的“我走了。”是气话。` | **不改**，只报告（引语作句子成分，反向搬移属删内容） |
| `他按下了“X”的按钮。` | **不改**（`”` 后不是句末标点，压根不匹配） |

**安全阀是「言语直接引出」**：开引号在行首，或前面紧跟 `：，。！？…；`
才判定为对话引语，才允许搬移。前接「的」「了」等（`他说的“X”。`）一律
不动。宁可漏修，不可误修。

**只做正向**是本规则的硬约束，反向会与不动点循环的补闭约定振荡
（原因见注意事项 17 与 references 决策 13）。

### 成对标点体检（P2，2026-10 新增）

书名号《》〈〉、圆括号（）、方括号［］、六角括号〔〕、直角引号「」『』、
方头括号【】的配对检查。**只出报告，不改正文**：不成对时补/删/移都
说得通，规则无从判断；且跨行配对（括号注跨段、书名号跨行）是合法排版，
必须按全文扫描而非逐行。

报告格式：`书名号：左 3 / 右 2（差 1）` + 未闭合左符号行号 / 多余右
符号行号。看到这段就把它当人工清单，别指望脚本替你决定。

## 关键注意事项（踩过的坑）

1. **不要做全局引号重排**：会把漏写引号造成的错位传播到全文，误改大量
   正常引号（实测误改 1700+ 处）。正确粒度是「逐行」。
2. **合法嵌套强调必须保护**：`"外"内"外"`（引号序列 L L R R）与「开闭
   颠倒」序列相同，纯自动交替会误伤。fix_quotes.py 已内置保护；
   E9/E12b 的行首 debris 清理同样跳过真嵌套行。
3. **智能交替重排的核心是「钉住」**：`：`,` 后的 `“` 是言语引出开引号，
   多段漏闭言语并存的行（如 `道：“A……道：“B……`）纯位置交替会按
   奇偶位把它错翻成 `”`。钉住后保留，期望闭引号时遇到的 `“` 若行内
   其后还有闭引号则视为新开引号（保留），否则翻正为 `”`。
4. **直引号必须交替替换**：不能一次性全替成左引号；先成对后单个。
4. **撇号与单引号要区分**：两个 ASCII 字母/数字之间的 `'` 是撇号
   （don't），其余位置才是引用单引号。
5. **URL/邮箱/HTML实体/小数/时间白名单**：`3.14` `1,000` `12:30` `http://`
   `a@b.com` `&lt;` `&#123;` 中的标点一律不动，靠「两侧均数字」
   「白名单正则」「±10 字符中文语境窗口」三重保护。
6. **风格化延长音不能折叠**：`～～～` `……` 可能是作者故意的语气延长，
   波浪线只做逐字符归一，省略号最多保留两个。
7. **引号规则必须放在不动点循环里**：（行首禁则合并 →）断链修复 →
   配对修复 → 单引号层级提升 → 空引号对修复 → 跨行倒置对话修复，
   互相影响（提升改写双引号布局后，原本判定为嵌套的单引号可能暴露
   为外层；合并改变行结构会影响逐行配对结果；配对补引号会在行尾生成
   `“”` 空对，必须再清掉；跨行修复必须在配对步之后，且合并成行内
   引号对避免跨行对引发连锁误修）。顺序执行一次不幂等（实测二次执行
   仍有 3+1 处改动），循环到一次完整迭代零改动才停。**新增引号相关
   规则时必须维持此性质。** 断链修复必须排在配对修复之前——先重排会被
   断链带偏，这是 2026-10 最大的教训。
8. **空引号对修复的所有模式都要求真实存在 `“”`**：因此不会误伤
   干净文本（合成回归：正常对话/嵌套/真嵌套/连续对话/引语中含
   言语动词全部 0 改动）。E9/E10 删行首 debris 引号时有奇数引号
   守卫（偶次是真嵌套，受 is_true_nested 保护，不能动）。
9. **空对修复的附带补闭是猜位置但不猜有无**：只在翻转倒置对暴露
   出未闭合开引号时，才在「最后一个言语结束句读」后补 `”`；
   找不到句读就留空、列入人工复核（实测 6 处）。行尾空对优先
   「移动开引号」而非「删除」——移动既补上漏引言语又不破坏平衡。
10. **奇数嵌套样貌行不是合法嵌套**：嵌套成对出现，引号数为奇数的行
    （如 `L L L R R`）即使长得像嵌套也不保护，走平衡修复并列入
    「疑似复杂嵌套行」人工复核报告。
11. **冒号后引号写反不可自动修正**（实测已回退）：`：”`→`："` 的语义
    翻转与逐行位置化交替重排根本冲突，前置或内嵌均导致二次执行仍
    有改动（振荡）。此项留人工，脚本只统计不改。
12. **`“` 后面紧跟句读 ≠ 一定是倒置闭引号**：`光泽。“这些都给你。”`
    里那个 `“` 是正常的对话开引号（旁白收尾后另起对话）。所以 D3
    必须有「引号深度 ≥1」这个守卫——只有前面已经有未闭合的开引号时，
    句读后的 `“` 才是倒置闭引号。2026-10 之前没有这条守卫，实测把
    几十行正常的开引号翻成了闭引号。
13. **「最左优先」是断链修复的命门**：同一行里「。后的倒置闭引号」
    和「夹在两个引号之间的短词」形状完全一样，谁先动手决定了结果。
    必须把两类候选合并、统一按位置从左往右处理，不能按规则优先级
    整类先跑。
14. **行尾那个孤零零的 `“` 是残骸，先删不要补**：`…支持。“` / `…反差的！“`
    这类行尾开引号，若先被补闭规则配对就会把前面整段旁白包进引号。
    删除只需要「末尾是 `“` 且前面是句读或 `”`」，是最安全的一步。
15. **人工校对结果是规则的最后裁判**：本组规则全部来自 35 例人工校对
    的反推与逐条回归（`tests/test_dangling.py`）。**不要凭「看起来像」
    加规则**——先把人工答案做成断言，再让脚本对齐；对不齐的
    （如「整句重复」「冒号后写反」）留在人工复核清单里，别硬猜。
16. **报告里的处数会重复计数**：不动点循环里同一行可能被反复修，
    统计值可能大于实际改动行数；判断是否幂等要看「第二次运行输出
    是否与第一次完全相同」，不要看报告合计是否为 0。
17. **引号内句末标点只做正向搬移（外→内），反向必振荡**：本流水线
    的补闭约定（E3/E4 附带补闭、D5、D7）一律把 `”` 补在句读**之后**，
    产出 `。”`。这是三条规则共同确立的方向。若再允许 `。”` → `”。`
    的反向搬移，两股力量方向相反，在不动点循环里必然来回振荡——与
    注意事项 11「冒号后引号写反」是同一个坑。因此：
    - `”。` `！”` `？”` → 搬进引号内（正向，安全，与补闭约定同向）
    - `。”` 后接正文（引语作句子成分）→ **只报告，不改**，进人工复核
      清单（`find_quote_period_suspects`）。改动等于删内容，且句号在
      内外本身有争议（`他说的“我走了。”是气话`）。
    - 该规则只搬标点、不增删引号，所以可以放在不动点循环**之后**，
      不会破坏循环已收敛的平衡状态。
18. **「言语直接引出」是正向搬移的安全阀**：只有开引号在行首、或前面
    紧跟 `：，。！？…；` 时才判定为对话引语，才允许把外面的句号搬进去。
    `他说的“X”。`（前接「的」）、`他按下了“X”的按钮。`（前接动词）
    一律不进入自动修复——前者句号位置有争议，后者根本不是句子结尾。
    宁可漏修，不可误修。
19. **成对标点只体检、不自动修**：书名号/括号不成对时，正确解法可能
    是补、可能是删、也可能是把内容移出，规则无从判断。参考实现
    macro-correct 的策略是「不成对就整对删掉」（其 `check_double`），
    会直接毁掉正文——本项目不采用。`check_paired_symbols` 只出报告，
    按**全文**扫描（跨行配对在小说里合法，逐行判断必然误报）。
20. **规则改动后的固定动作**：先跑 `tests/test_multigenre.py`（三种体裁
    干净文本零改动），再跑 `tests/test_dangling.py` 及其他专项测试。
    前者防「为修 A 书而伤 B 书」，后者防「为修新病而误伤旧症」。
