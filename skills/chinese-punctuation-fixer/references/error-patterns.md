# 中文双引号错配：错误类型与判断规则

本文件沉淀了中文小说/文本中「双引号（" "，U+201C / U+201D）错配」的常见错误类型与
判断经验，供修复时参考。核心结论来自对一部约 1.2 万行小说的实测（约 950+ 处错误）。

## 引号字符

| 名称 | 字符 | Unicode | 说明 |
|------|------|---------|------|
| 左双引号 | " | U+201C | 对话/强调的「开」 |
| 右双引号 | " | U+201D | 对话/强调的「闭」 |
| 左单引号 | ' | U+2018 | 引号内嵌套引用 |
| 右单引号 | ' | U+2019 | 引号内嵌套引用 |

注意：不要与 ASCII 直引号 `"`（U+0022）混淆。修复前先用 `collections.Counter`
统计各引号字符数量，确认使用的是全角中文引号。

## 错误类型

### 类型 A：对话开闭引号颠倒（最常见，占绝大多数）

对话开头本应 `"` 却写成 `"`，结尾本应 `"` 却写成 `"`。

- 例：`"啊！不许打人家那儿！你太过分了！"` → 应为 `"啊！...！"`
- 特征：行首引号是 `"`（右），行尾引号是 `"`（左）
- 分布规律：实测中这类错误从某一行（约 8593 行）起密集出现直到文末，
  前半部分基本正常。即错误往往是「局部密集」而非均匀分布。

### 类型 B：冒号后开引号写反

冒号引出对话，后面必须是左引号 `"`，却写成了 `"`。

- 例：`：` → 应为 `：``（约 38 处）
- 覆盖全角冒号 `：` 和半角冒号 `:`。

### 类型 C：引号漏写

对话只写了开头或只写了结尾（奇数个引号）。

- 缺开引号：`道：这位公子...` → `道："这位公子...`
- 缺闭引号：`"咦？...肏烂不可！` → 末尾补 `"`

### 类型 D：嵌套/特殊混乱（少量）

- 单引号误用：`'啊！"` → `"啊！"`
- 嵌套方向混乱：`"'浙西老淫雄'与'黔北屌霸王'` → `"浙西老淫雄"与"黔北屌霸王"`
- 末尾多余：`……""` → `……"`

### 类型 E：单引号当对话/着重引号用（层级错误）

GB/T 15834-2011 规定嵌套时「外双内单」——单引号只能作双引号内的
嵌套层。但作者常把单引号当对话引号或着重引号用：

- 例：`'好啊，那就来吧！'` → 应为 `"好啊，那就来吧！"`
- 例：`'浙西老淫雄'与'黔北屌霸王'` → `"浙西老淫雄"与"黔北屌霸王"`

**判定**：双引号深度状态机（`“`+1 `”`-1）之外的 `' '` 一律提升
为 `""`——深度外不可能是合法嵌套；深度内的保留（合法嵌套）。
ASCII 字母间的 `'`（don't）是撇号，不参与。

**注意区分**：嵌套合法（`"他说'你好'"`）与层级错误（`'你好'`）
序列相同，**深度**才是判据，不是序列形状。

**实测分布**（《覆雨翻云》3.8 万行）：590 个单引号中 337 个外层
误用、253 个合法嵌套；《侠女荡心》1.2 万行：4 个误用、44 个嵌套。
常规小说单引号总量应远小于双引号（约 1/50），**单引号数量异常偏多
时优先怀疑此类错误**。

### 类型 F：空引号对（`“”`，双引号之间没有内容）

两大来源：

1. **作者倒置引号习惯 + 配对补引号叠加**：作者开引号写 `”`、闭引号
   写 `“`，配对修复补闭引号时在行尾生成 `“”`。
   - 例：`...成长。“`（作者倒置换闭引号）→ 补 `”` → `...成长。“”`
   - 行尾 `标点+“”` 是最高频形态（实测 81/130）
2. **作者原文自带的残骸**：`”X“”`（倒置强调对+多余闭引号）、
   `“”X“”`（包裹残骸）、行首/段中孤立 `“”`。

**修复**：fix_empty_quote_pairs 的 E1-E10（见 punctuation-rules.md
第二节）。核心思路：
- 倒置对（`”X“”`/`[：，]”X“”`）翻转为正常对，**附带补闭**暴露出的
  未闭合开引号（作者对话开了头没结尾）
- 行尾空对优先**移动开引号**到漏引言语前（平衡不变），言语动词后
  内容缺失或无情绪标记的长旁白才删除
- 行首 `“` 包裹解说语（含言语动词+`：，`，或≥10字旁白+`“言语”`）
  是 debris，删除；奇数引号守卫保护真嵌套行

**实测**：《覆雨翻云》130 处 → 0，125 行改动，`: ”` 53→21，
平衡 14120/14120 → 14087/14081（差 6，全部为作者原文未闭合对话，
已列入人工复核）；二次执行 0 改动（幂等）。

### 类型 H：复合引号错误（旁白误加引号 / 倒置强调对 / 漏引言语）

《覆雨翻云》行 7935 是典型复合错误行（一句话 11 个引号 4 类错误）：

| 错误 | 原文片段 | 修复 |
|------|---------|------|
| 旁白误加引号 | `“房间不停的响着”` | 删开引号（旁白不该加引号） |
| 倒置强调对 | `”啪、啪“的肉与肉碰撞声` | `“啪、啪”的`（「的」=定语信号） |
| 漏引言语 | `”啊……公子……“听着` | `”“啊……公子……”听着`（感叹词开头+情绪标记） |
| 行尾多余闭引号 | `……鸡巴。”` | 删（前有句读且右>左） |

修复规则 E11-E15（见 punctuation-rules.md 第二节）。**判定核心**：
- 「的」在引号后 = 定语，前面的 `”X“` 必然是倒置强调对
- 感叹词（啊喔嗯呜唔哼哈哎）开头 + 情绪标记（……！？）= 漏引言语
- 行首 `“` 与第二个 `“` 之间无其他引号 = 行首 debris（解说误加引号）

**实测**：行 7935 修复后序列 `“”“”“”“”“”`（10 引号平衡），
全文唯一未闭合行闭合，差 1 → 0。

### 类型 I：多段漏闭言语并存（智能交替重排的动因）

作者常开了头没结尾（`道：“A……` 后直接接旁白/新对话）。一行多段
漏闭言语并存时（如 `道：“蜿儿……道：“下次……“扑味”`），纯位置
交替重排会按奇偶位把正常开引号 `“` 错翻成 `”`（产生 `：”` 倒置开
引号）。

**修复**：智能交替重排——钉住 `：`/`,` 后的开引号；期望闭引号时遇到
`“` 若行内其后还有闭引号则视为新开引号（保留），否则翻正。

**实测**（《覆雨翻云》用户修改版）：`：”` 21+ → **0**，多段漏闭行
开引号全部正确保留。

### 类型 G：跨行倒置对话（行N末尾倒置开引号 + 行N+1倒置闭引号）

作者倒置引号习惯跨行出现：

```
“秦柔侧着臻首，露出一个顽皮的笑容，模样可爱之极，柔声道：”
你还想怎么样？“
```

- 行N：行首 `“` 是 debris（包裹解说语）；行N末尾 `”` 是**倒置开引号**
  （言语动词+`：，`之后，作者把开引号写成闭引号）
- 行N+1：首个 `“` 是**倒置闭引号**（作者把闭引号写成开引号）

**作者本意**：`秦柔侧着臻首……柔声道：“你还想怎么样？”`

**判定**（防误伤）：
- 行N的引号只允许出现在动词+`：，`+`”`之后——行内含其他引号则不是
  本模式（如 `《史记》说：“七月丙寅……二世曰：”`，行内有正常开引号）
- 行N+1的 `“` 前必须是无引号正文——`“`直接开头是正常对话开头
  （如 `“啊……好热呀……`），不属于本模式

**修复**：删行N的 debris `“`、行N末尾 `”`→`“`、行N+1首个 `“`→`”`，
两行合并（合并成行内引号对，避免跨行对让逐行平衡/未闭合报告产生
假阳性）。

**实测**：《覆雨翻云》1 处（行 17772-17773）。

### 类型 J：断链引号（OCR/AI 改写稿专属，2026-10 新增）

与类型 A 的区别：类型 A 是「整行开闭颠倒」，类型 G 是**一行之内多处
断链**——前半句用倒置闭引号、后半句用正常闭引号，或对话开头的开引号
整段丢失。交替重排对这类行会「放弃」或按奇偶位误翻。

- 倒置强调对：`他按下了“添加到通讯录“的按钮` → `…“添加到通讯录”的按钮`
- 对话＋旁白＋新对话：`“这些都给你。“她的声音发紧，“我们两清。”`
  → `“这些都给你。”她的声音发紧，“我们两清。”`
- 行首漏开引号：`我只是还给你而已，“他俯身靠近，“你怎么就受不了了？`
  → `“我只是还给你而已，”他俯身靠近，“你怎么就受不了了？”`
- 行首叠引：`““老师，您接触的优秀学生…` → `“老师，您接触的优秀学生…`
- 行尾孤立开引号：`…月票支持。“` → `…月票支持。`

**识别特征**：整行 `“` 数明显多于 `”` 数（净差 ≥1），且**同一行里既有
正常的 `”` 又有本该是 `”` 的 `“`**。这类稿子通常还伴随大量 OCR 错字
（`栀子`→`子`、`瞥`→`警`），标点修复不负责改错字，需在报告里说明。

**修复**：fix_dangling_quotes 的 D1–D7（预算法 + 深度守卫 + 最左优先），
详见 punctuation-rules.md 第二节附。**注意先修断链再做交替重排**，
顺序反了会残留大量不平衡行。

## 关键判断规则

### 1. 合法括号序列原则

一行内引号序列必须满足：任意前缀中左引号数量 >= 右引号数量，且最终左右相等。
即「左引号开、右引号闭」的严格交替（可嵌套）。

### 2. 真嵌套强调（需保护，不能动）

中文正确用法中，引号内再引用应改用单引号 `''`，但很多作者沿用双引号嵌套：
`"外"内"外"`，引号序列为 `L L R R`。

特征（三者同时满足才判定为真嵌套）：
- 序列以 `"` 开头
- 序列以 `"` 结尾
- 序列中同时含连续的 `""`（LL）和 `""`（RR）

这类行本身正确，**修复时必须保护不动**，否则「逐行交替重排」会把它误改成
`L R L R`，破坏内层强调。实测这类真嵌套数量很少（约 5 处），但不可忽略。

### 3. 逐行 vs 全局

- **逐行**处理是正确粒度：中文小说对话基本「每段独立、每行完整闭合」，
  不存在正常的跨行对话。
- **全局**交替重排会把「漏写引号」造成的错位传播到后面所有引号，
  导致大量误改（实测误改 1700+ 处），切勿使用。

### 4. 奇数引号行 = 漏写

一行内引号数量为奇数，说明漏写/多写了一个引号。需按语义判断补/删方向：
- `左 < 右`：缺左引号，优先在冒号 `：` 后补，否则行首补
- `左 > 右`：缺右引号，行尾补
- 3 个引号且含换说话人（如 `..."玉儿也...`）：需在换人处补左引号

## 标准修复流程

1. **统计**：`collections.Counter` 统计 `"` `"` `'` `'` 各出现次数，
   判断总体是否平衡（左右双引号数量差即「纯左写右/纯右写左」的错误数）。
   单引号数量异常偏多时怀疑类型 E（层级错误）。
2. **定位真嵌套行**：按上述规则筛出 `L L R R` 的合法嵌套行，加入保护名单。
   **引号数为奇数的行不进保护名单**（见「奇数嵌套样貌行」）。
3. **逐行交替重排**：对非保护、非奇数的行，按「奇数位=左、偶数位=右」重排。
4. **处理奇数行**：补/删引号，方向按语义判断。
5. **单引号层级提升**：双引号深度之外的 `' '` → `""`，深度内保留，
   撇号保留。
6. **不动点循环**：步骤 2-5（含行首禁则合并）互相影响，循环到一次
   完整迭代零改动。一次顺序执行不幂等。
7. **验证平衡**：最终左右引号数量必须相等；若不等，用栈配对法（遇 `"` 入栈、
   遇 `"` 出栈，栈空遇 `"` 记「多余右引号」，末尾栈非空记「未闭合左引号」）
   定位残余错误。
8. **幂等验证**：对成品再跑一次 `--check`，所有规则修改数必须为 0。

## 奇数嵌套样貌行（重要教训）

引号数为**奇数**的行，即使序列长得像嵌套（L 开头、R 结尾、含 LL/RR），
也不可能是合法嵌套——嵌套成对出现，奇数必然有一个没闭合。

**踩过的坑**（《覆雨翻云》行 7974）：`L L L R R`（5 个引号）命中
`is_true_nested` 保护被原样保留，导致全局左引号比右引号多 1、永远
无法闭合。修正：**奇数行一律不走嵌套保护**，走平衡修复，同时列入
「疑似复杂嵌套行」报告（quote_odd_nested 行号）供人工复核。

## 已知局限

- 纯自动的「交替重排」无法区分「真嵌套」与「开闭颠倒」，两者引号序列相同。
  必须靠保护名单兜底；奇数行不走保护（见上节）。
- 奇数引号行的补/删方向依赖语义，自动化只能覆盖最常见情况（行尾补闭引号），
  复杂情况（多说话人换行、内心独白）需人工确认。行尾已是闭引号时不补
  （缺的是别处的开引号），留人工。
- **冒号后引号写反**（`：”`）不可自动修正：语义翻转与位置化重排冲突，
  实测两种方案均振荡（二次仍改 1060/88 处），已回退，留人工。
- **空引号对**（`“”`）已由 E1-E10 自动修复；附带补闭找不到安全句读时
  留人工（实测 6 处）。
- 若文本混用单引号做对话引号，用单引号层级提升规则处理（见类型 E），
  无需另行处理。
