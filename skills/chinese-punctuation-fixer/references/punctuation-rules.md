# 中文标点规范化：规则总表与设计决策

本文件是 chinese-punctuation-fixer 技能的知识沉淀。规则依据
GB/T 15834-2011《标点符号用法》与小说 txt 整理实践，参考了
typeset、novelty、cjk-text-polish 等开源项目的做法。

## 一、转换规则总表

### 1. 省略号（规范形式：六连点 `……`，占两字宽）

| 非规范写法 | 归一结果 | 说明 |
|-----------|---------|------|
| `...`（三个英文点） | `……` | 最常见 |
| `。。` / `。。。` | `……` | 句号冒充省略号 |
| `．．．`（全角点） | `……` | |
| `···` / `・・・` | `……` | 间隔号冒充 |
| `‥‥` / `⋯⋯` | `……` | 数学省略号 |
| `…………`（4+ 个 U+2026） | `…………`（两个） | 国标允许的上限 |
| 混合串 `。。。...` | `……` | maximal run 整体归一 |

实现要点：一次正则 `[.。．·・⋯‥…]{2,}` 遍历所有 maximal run 整体替换，
天然幂等；纯 U+2026 串 ≤2 个保留（合法），≥3 个折成两个。

### 2. 破折号（规范形式：两连 `——`）

| 非规范写法 | 归一结果 |
|-----------|---------|
| `--`（两个连字符） | `——` |
| `――`（全角减号） | `——` |
| `──`（制表符） | `——` |
| `———`（3+ 个 em dash） | `——` |
| `--—` 等混合 | `——`（不动点循环） |

**例外**：整行只有装饰字符的分隔线行（如 `----------`）原样保留，
这是章节分隔线，不是破折号。

### 3. 波浪线（规范形式：全角 `～` U+FF5E）

| 非规范写法 | 归一结果 |
|-----------|---------|
| `~`（ASCII） | `～` |
| `˜` `∼` `〜` `～`(U+301C) | `～` |

**关键决策：逐字符替换，不折叠连续串**。小说中 `～～～` 是风格化延长音
（如 `吸溜～～～`、`噗～～`），折叠会损失作者风格。实测踩过这个坑：
第一版把 `～～～` 折叠成 `～`，被证明是破坏性的。

### 4. 重复标点

| 模式 | 处理 | 理由 |
|------|------|------|
| `。。` `，，` `、` `；；` `：：` | 合并为单个 | 几乎必然是错误 |
| `,,` `;;` `::`（半角） | 合并为单个 | 同上 |
| `！！！` `？？？` | **默认保留** | 小说中常作风格化强调；`--collapse-bang` 才合并 |
| `！！！！` 混排半角 | 同上 | |

### 5. 全角字母数字 → 半角

`Ａ-Ｚ` `ａ-ｚ` `０-９` → ASCII（Unicode 偏移 0xFEE0）。
只转字母数字，不动全角标点。全角空格 U+3000 不动（可能是首行缩进）。

### 6. 英文直引号 → 中文弯引号

| 原文 | 结果 | 规则 |
|------|------|------|
| `"你好"` | `"你好"` | 双引号按出现顺序**交替**配对 |
| `'你好'` | `'你好'` | 单引号同样交替 |
| `don't` `John's` | `don’t` `John’s` | **撇号识别**：两个 ASCII 字母/数字之间的 `'` 是撇号，转 U+2019，不参与配对 |
| `'90s` | 视作引号 | 边界情况，可接受 |

**顺序原则（先成对后单个）**：先双引号后单引号；成对交替替换，
不能一次性全替成左引号。

### 7. 半角标点 → 全角（中文语境感知）

映射：`,`→`，` `.`→`。` `!`→`！` `?`→`？` `:`→`：` `;`→`；`
`(`→`（` `)`→`）`

**三重保护**（这些位置不动）：
1. **数字语境**：两侧均为数字时不转——保护 `3.14`（小数）、
   `1,000`（千分位）、`12:30`（时间）
2. **URL/邮箱/HTML实体白名单**：`(?:[a-zA-Z][a-zA-Z0-9+.-]*://|www\.)\S+`
   与邮箱正则命中的区间整体跳过；HTML 实体
   `&(?:[a-zA-Z][a-zA-Z0-9]*|#[0-9]+|#[xX][0-9a-fA-F]+);`
   （如 `&lt;` `&gt;` `&amp;` `&#123;` `&#x1F;`）同样整体跳过
3. **中文语境窗口**：前后各 10 个字符内没有任何中文（汉字/中文标点/
   全角字符/弯引号）时不转——保护纯英文句子

另有细节保护：`://` 后的冒号（URL 协议）、`No.1` 式序号缩写
（前字母后数字）。

**已知边界**：纯英文段落中嵌在中文长句里的英文短语（如
`他说 Oh my god!好厉害`），其 `!` 会被转换——这是可接受的行为
（整体是中文语境）。

## 二、引号配对修复规则

详见 error-patterns.md，要点：
- **智能交替重排**（fix_alternate）：逐引号从左到右、期望方向从「左」
  开始交替。两条保护：
  1. `“` 紧跟 `：`/`，` 之后 = 言语引出开引号，钉住不翻
  2. 期望闭引号时遇到 `“`：行内其后还有闭引号 → 上一段言语漏写闭
     引号，此 `“` 是新开引号（保留，继续期望闭）；否则是倒置闭引号
     （翻正为 `”`）
  纯位置交替在多段漏闭言语并存的行（如 `道：“A……道：“B……“扑味”`）
  会按奇偶位把正常开引号错翻成 `”`，智能版全部正确保留
- 行首 debris 引号（双开引号型）：行首 `“` 与第二个 `“` 之间无其他
  引号 → 行首的是解说误加引号（debris），删除后按奇数行补齐
- 真嵌套强调保护（引号序列 `L L R R`，如 `"外"内"外"`）；
  **但引号数为奇数的行不保护**——嵌套成对出现，奇数行不可能是
  合法嵌套，走平衡修复并列入人工复核（quote_odd_nested）
- 奇数引号行补引号（缺左优先冒号后补，缺右行尾补）；
  闭引号开头的行不补左引号（防 `""` 空引号）；
  行尾已是闭引号时不补右引号（防 `””` 振荡）
- 单引号层级提升（见下节）
- **禁止全局重排**（漏写错位会传播，实测误改 1700+ 处）

### 智能交替重排实测（《覆雨翻云》用户修改版 3.0 万行）

| 指标 | 纯位置交替 | 智能交替 |
|------|-----------|---------|
| `：”`（冒号后倒置开引号） | 21+（误翻产生） | **0** |
| 多段漏闭行的开引号 | 按奇偶位误翻 | 全部正确保留 |
| 行首 debris 行 | 错翻后留 `：”` | debris 删除+开引号保留+闭引号补齐 |

### 引号残骸清理规则（E11-E15，《覆雨翻云》行 7935 实战）

行 7935 是典型的多错误复合行：`“嗯……”“房间不停的响着”啪、啪“的…
…和”噗滋、噗滋“的……叫出口：“啊……”啊……公子……“听着……鸡巴。”`
包含旁白误加引号、倒置强调对、漏引言语、行尾多余闭引号四类错误：

| 规则 | 模式 | 修复 | 判定要点 |
|------|------|------|---------|
| E11 倒置强调对+的 | `”X“的` → `“X”的` | X≤10字无句读 | 「的」是定语信号（`啪、啪的声音` 必强调） |
| E12 旁白开引号残骸 | `”“X“Y”` → `”X“Y”` | 紧邻对中的旁白开引号 | 旁白误加引号（`“房间不停的响着”`） |
| E12b 行首旁白残骸 | `^“X“Y”` → `X“Y”` | 行首旁白开引号 | Y 短强调；真嵌套行保护 |
| E13 漏引言语 | `”X“` → `”“X”` | 补开引号+倒置闭引号翻正 | X 感叹词开头+情绪标记；`“`后30字内无闭引号才动（防误伤正常开引号 `”啊……“我们去吧”`） |
| E14 行尾多余闭引号 | 行尾 `”` → 删 | 旁白残骸 | 前有句读且行内右>左（只在改善平衡时动手） |
| E15 行首 debris+倒置开引号 | `“解说[：，]”言语$` → `解说[：，]“言语` | 删 debris+翻正 | 交替重排曾把第二个 `“` 错翻成 `”`（产生 `：”`）；漏写闭引号由配对步补齐 |

### 引号层级规则（GB/T 15834-2011：外双内单）

国标 4.8.3.4：引号里面还要用引号时，外面一层用双引号，里面一层用
单引号。即**单引号只能作双引号内的嵌套层**；当对话/着重引号用属
层级错误。

但小说作者常把单引号当对话引号用（`'你好'`）。promote_single_quotes
的处理：

| 情形 | 处理 | 判定 |
|------|------|------|
| 双引号深度**之外**的 `' '` | 提升为 `""` | 深度状态机：`“`+1 `”`-1（不低于 0）；depth==0 的单引号不可能是合法嵌套 |
| 双引号深度**之内**的 `' '` | 合法嵌套，保留 | depth>0 |
| 两个 ASCII 字母/数字之间的 `'` | 撇号，保留 | don't / John's，不参与任何配对 |

**实测**（《覆雨翻云》3.8 万行）：原文 590 个单引号中 337 个为
外层误用（提升），253 个为合法嵌套（保留）。《侠女荡心》1.2 万行：
4 个提升、44 个嵌套保留。

### 引号三规则的不动点循环

行首禁则合并 → 配对修复 → 单引号提升，三者互相影响：

1. 提升把 `'` 改写成 `"`，改变双引号布局——原本判为嵌套的单引号
   可能暴露为外层（实测行 7939 `啪、啪'的肉与肉碰撞声和'`，平衡后
   嵌套不再成立，二次执行又可提升）
2. 合并改变行结构——闭引号开头的续行若先做配对重排，行首闭引号被
   交替规则错改成开引号，续行永远合不回去

顺序执行一次不幂等（实测二次执行仍有 4 处改动）。解法：三者放进
不动点循环，迭代到一次完整迭代零改动。最终状态与步骤顺序无关，
重复执行幂等。**新增引号相关规则必须维持此性质。**

### 引号四规则的不动点循环

加入「空引号对修复」后为四规则（行首禁则合并 → 配对修复 → 单引号
提升 → 空引号对修复）。配对补引号会在行尾生成 `“”` 空对，必须再
清掉；清理后行可能变奇数，下一轮配对的行尾闭引号守卫保证不再振荡。
再加入「跨行倒置对话修复」后为五规则；跨行修复必须在配对步之后，
且合并成行内引号对，避免跨行引号对引发连锁误修。

### 跨行倒置对话修复规则（fix_crossline_inverted_quotes）

作者的倒置引号习惯跨行出现（《覆雨翻云》行 17772-17773 实战）：

```
“秦柔侧着臻首，露出一个顽皮的笑容，模样可爱之极，柔声道：”
你还想怎么样？“
```

行N末尾 `”` 是倒置开引号（言语动词+`：，`之后），行N+1首个 `“`
是倒置闭引号。作者本意：解说后引出对话。

**修复**：删行N的 debris `“`（若有）、行N末尾 `”`→`“`、行N+1首个
`“`→`”`，两行合并：

```
秦柔侧着臻首，露出一个顽皮的笑容，模样可爱之极，柔声道：“你还想怎么样？”
```

**判定**：
- 行N：`^\s*“?(无引号*[言语动词][：，])”$`——引号只允许出现在动词+
  `：，`+`”`之后；行内含其他引号则不匹配（避免误伤带对话的解说行）
- 行N+1：`“`前为无引号正文（`“`直接开头是正常对话，不匹配）

**为什么合并**：行N末尾的孤立开引号若保留，配对修复会在行尾补 `”`
生成 `“”` 空对；且跨行引号对会让逐行平衡与未闭合报告产生假阳性
（开引号在行N、闭引号在行N+1，逐行栈配对会认为行N未闭合）。合并
成行内引号对后天然稳定、幂等。

**为什么只在行N+1的 `“` 是首个引号时才动**：若行N+1以 `“` 直接开头，
那是正常对话开头（如 `“啊……好热呀……`），行N末尾的 `”` 是另一种
缺陷（双重开引号），不属于本模式。

### 空引号对修复规则（fix_empty_quote_pairs）

`“”`（双引号之间没有内容）的两大来源：① 作者倒置引号习惯（开引号
写 `”`、闭引号写 `“`）与配对补引号叠加；② 作者原文自带的包裹残骸。
**实测**（《覆雨翻云》3.8 万行）：130 处，其中 81 处为行尾
`标点+“”`、43 处为段中 `”X“”`/`“”X“”`、6 处为提升产生。

规则（逐行按序，E1-E10 全部要求真实存在 `“”` 或明确的 debris
结构，故不误伤干净文本——合成回归 9 组合法用法 0 改动）：

| 规则 | 模式 | 修复 | 说明 |
|------|------|------|------|
| E1 包裹空对 | `“”X“”` | `“X”` | 整行包裹的对话/强调 |
| E2 行首空对 | `^“”` | `“` | 行首多余开引号 |
| E3 倒置对话对 | `[：，]”X“”` | `[：，]“X”` | 冒号/逗号后倒置的对话对 |
| E4 短强调倒置对 | `”X“”` | `“X”` | X≤10字且无句读（排除正常闭引号+新引语） |
| 附带补闭 | 翻转后首个开引号未闭合 | 在最后一个 `。！？…` 后补 `”` | 作者对话开了头没结尾；找不到句读则留人工 |
| E5 行尾移动 | `”X“”$` | `”“X”` | X 含 `……！？`：上一闭引号正常、X 是漏引言语 |
| E6 行尾残骸 | `X“”$` | `X` | 其余行尾空对直接删除（不猜语义） |
| E7 冒号言语 | `：X“”` | `：“X”` | 冒号后漏引言语+空对 |
| E8 整行强调 | `A“”B“C”$` | `A“B”C` | A 非空：强调对前半边丢失 |
| E9 行首 debris | 行首 `“`+解说语（言语动词+`：，`）+`“` | 删行首引号 | 仅奇数引号行 |
| E10 行首 debris | `“`+长解说(≥10字)+`“言语”$` | 删行首引号 | 排除短嵌套残引 |

**为什么行尾空对优先「移动开引号」而非「删除」**：`”X“”` 结构里，
上一个闭引号通常正常（对话 1 已闭合），X 是作者忘了加开引号的
言语。把 `“` 移到 X 前面既补上漏引言语、又不破坏平衡（引号数不变）；
只有 X 以 `：`/`，` 结尾（言语动词引出但内容缺失）或无情绪标记
（`……！？`，是旁白不是言语）时才删除。实测判别：含情绪标记的
（`”喔……小坏蛋……“`）移动，无标记长旁白（`”他站在那里...“`）
删除——后者若移动会把解说括进引号。

**振荡防护**：配对补引号↔空对删除可能互相抵消（如行尾 `“` 被补
`”` 成 `“”` 再被删回）。不动点循环检测「本轮净零改动」即退出，
最终状态是修复步之后的状态（无空对），流水线级幂等。

**为什么附带补闭只猜位置不猜有无**：翻转倒置对会暴露「作者开了头
没结尾」的对话（如 `道：“带我去……[ narration ]道：“别担心……”`）。
在「未闭合开引号之后、下一个引号之前的最后一个 `。！？…`」后补 `”`
恢复作者本意；找不到句读就留空列入人工复核（实测 6 处，如
`说道：“我有三个师傅……不过其中一位“回春手”`——话音直冲强调引号，
无安全补闭点）。

## 二·附、断链引号修复规则（fix_dangling_quotes，D1–D7）

**来源**：《冰山女教师的反差沉沦》（4 万行 / 200 万字，OCR+AI 改写稿）
用户人工校对 35 例反推 + 逐条回归。判定依据来自人工答案，不是猜测。

### 病根

1. 闭引号一律敲成开引号（`。“`、`， “`、`！”` 混用）；
2. 对话开头的开引号被吃掉（正文直接起句）。

两种习惯相邻时，逐行交替重排被带偏：`…了。“她声音发紧，“…”` 这种
「对话＋旁白＋新对话」会被读成「旁白＋对话」，整行放弃不动。实测
交替重排跑完仍有 242 行不平衡、净差 273 个引号。

### 预算法（核心机制）

```
budget = line.count(“) - line.count(”)
每次把 “ 翻正为 ”  →  L-1、R+1  →  budget -= 2
```

- `budget == 0` 的行**不进规则**：合法嵌套 `“外“内”外”` 与「开闭颠倒」
  序列形状相同，但它是平衡行，天然被排除在预算分支外；
- 只有「左引号确实过多」才动手 → 不会把好行弄坏；
- 修平后 budget 归零，二次执行零改动（幂等）。

### 规则表

| 规则 | 模式 | 必要条件 |
|---|---|---|
| D1 行首叠引 | `^““+X` → `“X` | — |
| D6 行尾孤立引 | `X句读“` → `X句读` | 前一字 ∈ `。！？…，”` |
| D2 倒置强调对 | `“X“` → `“X”` | X≤10 字、无任何句读、`“` 的深度 ≥1 |
| D3 倒置闭引号 | `。！“` → `。！”` | 非行尾、深度 ≥1 |
| D5 补闭引号 | 行尾 `。` → `。”` | budget==1 且最后一个引号在行首或紧跟句读 |
| D4 补开引号＋翻正 | `X，“旁白，“Y` → `“X，”旁白，“Y` | 见下方四条 |
| D7 补开引号 | `X？…”旁白` → `“X？”旁白` | budget==1、首个 `”` 前无引号且不含句号、该段以 `？！…` 收尾 |

执行顺序：**D1 → D6 →（D2/D3 合并取最左）→ D5 → D4 → D7**。

### D4 的四条必要条件

1. 行内第一个 `“` 紧跟 `。！？…，`；
2. 该 `“` 之前没有句号「。」——句号是旁白收尾信号，`？`/`！` 常是
   对话自己的收尾（`九十分可以吗？老师？`）；
3. 该 `“` 之前无引号，且末尾 8 字内无言语动词
   （`说道问答喊叫嚷骂笑叹`）——`…他说，“…”` 是旁白引出对话；
4. 该 `“` 之后紧跟「旁白＋下一段引语」，旁白 ≥4 字——排除行尾残句。

### 三条顺序铁律（都踩过）

- **D6 先于 D2/D3**：行尾孤立 `“` 不先删，会被补闭规则配成 `“…”`，
  把整段旁白包进引号（实测误伤 20 行）。
- **D2 与 D3 按位置统一取最左**，不按规则整类先跑：
  `…了。“她特意加重了“敬重”二字` 里两处形状相同，只有最左那个
  （句读后的 `“`）才是倒置闭引号。
- **D5 先于 D4**：行尾就缺一个闭引号时直接补；先补开引号会把
  「旁白＋新对话」读成「对话＋旁白」。

### 深度守卫（2026-10 最大教训）

`“` 紧跟 `。！？…` **不等于**倒置闭引号：
`光泽。“这些都给你。”她的声音…` 里那个 `“` 是正常的对话开引号
（旁白收尾后另起对话）。必须加「该 `“` 处引号深度 ≥1」的守卫。
去掉这条守卫，实测把几十行正常开引号翻成了闭引号。

### 效果

| 指标 | 只跑交替重排 | 加断链规则 |
|---|---|---|
| 左右引号净差 | 273 | 71 |
| 不平衡行数 | 242 | 46 |
| 人工 35 例完全命中 | 0 | 19（余 4 例未动、12 例需内容级判断） |
| 正文完整性 | — | 去标点后逐字一致（1,748,561 字） |

**未纳入自动修复的两类**（留人工复核）：① 原文整句重复
（`“A“吧？”“A吧？”`）；② 冒号后引号写反（`调侃：”`）——后者与逐行
位置化重排冲突，会振荡（见注意事项 11）。

## 三、设计决策记录

1. **为什么省略号用 maximal run 单次遍历，而不是逐条正则**：
   组合写法（`。。。` 紧跟 `...`）顺序应用多条正则会产生新的可匹配
   模式（`…………`），导致非幂等，且重复计数。单次遍历 run 整体归一
   一处只算一次，天然幂等。

2. **为什么计数要「只在文本真正变化时」**：`re.subn` 把无变化替换
   （如 `……`→`……`）也计入次数，导致报告虚高（实测虚高 70 倍：
   5718 vs 真实 79）。所有规则函数都规避了这一点。

3. **为什么波浪线不折叠**：见上，风格保留优先。

4. **为什么 `!!`/`??` 默认不合并**：小说作者用叠用表达情绪强度，
   是风格而非错误；提供开关交给用户决定。

5. **为什么保留 BOM 和 CRLF**：用户文件可能有既有约定，
   修复工具不该擅自改变文件级属性。

6. **为什么行首标点禁则从「只报告」升级为「自动修复」**：用户确认过
   决策——上下行明显是一句话的（续接标点开头）合并为一行，句号开头
   明显不对的删除，省略号开头可能是刻意留白保留。合并只发生在紧邻的
   上一行且避开标题/空行/分隔线，风险可控。若用户场景不同（如保留
   原始分行），用 `--no-linehead` 关闭。

7. **为什么 HTML 实体要进白名单**（《覆雨翻云》实战发现）：小说里
   出现了整行的 `&lt;&gt;&lt;&gt;...` 实体串（类似马赛克装饰行）。
   实体的分号位于中文语境（行首全角空格、行尾邻中文），被规则转成
   全角 `；`，实体被打断成 `&lt；` 失去转义含义；且同排上下文连锁
   反应破坏幂等性（二次执行又改 4 处）。HTML 实体与 URL/邮箱同类——
   都是「内部标点有语义、不能动」的片段，必须整体保护。

8. **为什么引号三规则要不动点循环**（《覆雨翻云》实战发现）：见
   第二节。提升与平衡互相暴露新问题，一次顺序执行留尾（实测二次
   仍有 3 个单引号可提升 + 1 处补引号）。循环到零改动后，状态与
   顺序无关、完全幂等。

9. **为什么奇数嵌套样貌行不保护**：嵌套成对出现，引号数为奇数的行
   即使序列长得像嵌套（L 开头 R 结尾含 LL/RR）也不可能是合法嵌套
   （《覆雨翻云》行 7974 `L L L R R`，曾被误保护导致全局差 1 无法
   闭合）。奇数行一律走平衡，并列入「疑似复杂嵌套行」人工复核。

10. **为什么冒号后引号写反不自动修正**（实测回退）：`：”`→`："`
    看似一条语义翻转规则，但与逐行位置化交替重排根本冲突——翻转
    改变引号身份，重排又依赖引号位置，两者交替作用产生振荡
    （方案一内嵌：二次仍改 1060 处；方案二计数守恒前置：二次仍改
    88 处）。强行修正会破坏幂等性这一底线性质，故保留验证过的
    稳定核心，此项统计后留人工。

11. **为什么空引号对修复的每个模式都要求真实存在 `“”`**（或明确的
    行首 debris 结构）：这是防误伤的关键设计。`”X“`（无尾随 `”`）
    这类「倒置对」模式曾考虑过，但会误伤正确文本
    （`“你好”她说“再见”` 中的 `”她说“` 会被错翻），故 E3/E4 一律
    要求尾随 `“”`。行首 debris 清理（E9/E10）用奇数引号守卫避开
    受保护的真嵌套行（L L R R 为偶数）。

12. **为什么行尾闭引号行不再补引号**（fix_quotes.py 守卫）：奇数行
    `左>右` 且行尾已是 `”` 时，缺的是别处的开引号（对话开了头没
    结尾）。行尾补 `”` 会生成 `””`，再被交替重排打回 `“”` 空对
    （实测振荡）。原样保留 + 未闭合引号报告，让缺陷对人工可见。

13. **为什么引号内句末标点只做正向（P1，2026-10）**：三步推演。
    ① 先查清既有约定：E3/E4 附带补闭把 `”` 插在最后一个 `。！？…`
    之后；D5 在行尾 `。` 后追加 `”`；D7 把开引号补在 `？！…` 收尾段
    之前。三条独立规则方向完全一致——**都认定「句末标点在引号内」**。
    ② 若新增反向搬移（`。”` → `”。`），它与上述三条方向相反，在
    不动点循环里必然来回振荡，与决策 10 同类型。
    ③ 因此只做正向（`”。` → `。”`），反向只报告。附带收益：本规则
    不增删引号、只搬标点位置，故可放在循环之外，不干扰收敛。
    安全阀是「言语直接引出」（行首或前接 `：，。！？…；`），否则
    `他说的“X”。` 这类句子成分引用也会被搬，属误修。

14. **为什么成对标点只体检不自动修（P2，2026-10）**：不成对时有三种
    解法（补一个、删一个、把内容移出），取决于语义，规则无法判断；
    而小说里跨行配对（括号注跨段、书名号跨行）是合法排版，逐行判断
    会大量误报。参考实现 macro-correct 用「不成对就整对删掉」兜底，
    会直接毁正文，本项目明确不采用，改为全文栈扫描 + 只出报告。

## 四、行首标点禁则修复规则（fix_line_start_punct）

用户确认过的三类决策：

| 行首字符 | 处理 | 理由 |
|---------|------|------|
| `，！？；：、）】》」』` | **合并到上一行** | 上下行明显是一句话，换行错位 |
| `——`+正文（如 `——他听不到的。`） | **合并到上一行** | 破折号引出下文，续接 |
| 整行只有 `——` | 不动 | 独立的中断/留白标记 |
| `。`（句号） | **删除**；删后整行空了连行删除 | 句号开头明显不对 |
| `。”`（句号后紧跟闭引号/闭括号） | 合并到上一行 | 是上一行被拆断的句尾，不是新句子 |
| `……`（省略号） | 不动，列入报告 | 可能是作者刻意留白/分隔 |
| `“`（开引号） | 不动 | 新对话开头，正常排版 |

**合并的保护条件**（任一不满足则不合并）：
- 上一行不存在 / 是空行（跨段落不合并）
- 上一行是章节标题（`第X章`/`序`/`尾声` 等正则）
- 上一行或本行是分隔线（整行装饰字符）

**实测案例**（《侠女荡心》11961 行）：
```
难道说……难道说那骚货……       难道说……难道说那骚货……！！！！！！！
！！！！！！！            →    （合并）
“夫人放心，你丈夫不是昏迷不醒嘛？”
——他听不到的。            →    “夫人放心，你丈夫不是昏迷不醒嘛？”——他听不到的。
```
共合并 11 行，删除 0 处；残留 21 处报告项 = 19 处省略号开头（保留）
+ 1 处独立 `——` + 1 处章节分隔线。

## 五、GB/T 15834-2011 速查（与小说相关的常用规则）

- 省略号：六连点 `……`，占两个字位置；省略号前后通常不加点号
- 破折号：两连 `——`，占两个字位置；破折号之前通常不加点号
- 引号嵌套：外层双引号 `""`，内层单引号 `''`
- **引号与句末点号的位置**：完整引用整句时，句末点号放**引号之内**
  （`他说：“我走了。”`）；引语作句子成分、只引局部时，点号放**引号
  之外**（`他说的“我走了”是气话。`）。这条是本项目 P1 规则的依据。
- **成对标点**：书名号《》可嵌套但需换用单书名号〈〉；括号（）可嵌套
  〔〕；成对标点必须成对出现，跨行也须闭合
- 并列书名号/引号之间通常不加顿号（《红楼梦》《三国演义》）
- 概数之间不加顿号（三四百人）；缩略并列可加（二、三产业）
- 数值范围用浪纹线 `～`，不用键盘波浪号
- 问号/叹号叠用最多三个

## 六、已知局限

1. **多说话人同行/内心独白**的奇数引号行：自动化只能覆盖最常见情况
   （冒号后补/行尾补），复杂情况需人工（报告 quote_odd_nested 行号）。
2. **真嵌套 vs 开闭颠倒**在引号序列上不可区分，靠保护名单兜底；
   若保护名单漏判会误伤。奇数行不适用保护（见决策 9）。
3. **中英文混排的句子级判断**：窗口启发式无法完美区分「中文句子里的
   英文短语」与「英文句子」，极端情况可能误转。
4. **冒号后引号写反**（`：”`）不自动修正，只统计留人工（见决策 10）。
   空引号对 `“”` 已由 E1-E10 自动修复（见第二节）；附带补闭找不到
   安全句读时留人工（实测《覆雨翻云》6 处）。
5. 本技能针对简体中文（大陆规范）；繁体（「」『』）需 `--trad-quotes`。
6. 半角 `[` `]` `<` `>` 未做转换（小说中常为作者注记或标题），
   如需统一需人工评估。
7. **引号内句末标点的反向搬移不做**（`。”` → `”。`）：与补闭约定方向
   相反，会振荡。只由 find_quote_period_suspects 报告（见决策 12）。
8. **成对标点不成对时不自动修**：补/删/移都有风险，只报告（见决策 13）。
9. **古诗词的标点风格**：部分版本刻意不加句末点号或用空格断句，
   规则不介入（多体裁回归集 `corpus/guwen.txt` 校验零改动）。
