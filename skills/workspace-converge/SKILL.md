# 空间收敛（两档）

## 中文速览

```
A 档·任务收尾（每次自动）：记结论 → 记坑（先查用户级无同条）→ 只清本轮新建的中间产物 → 当天日志追加一条
B 档·空间收敛（用户说「收敛」）：先量 → 快照 → 清单待确认 → 压记忆（原子写）
        → 五项核验 → 蒸日志（带索引）→ 清草稿脚本 → 搬家后复验 → 收敛记录 → 一页报告
```

铁律三句：**候选区可以脏，正式记忆必须干净；拿不准就保留；验钥匙的清单不能凭记忆列，要跑脚本。**

## A 档 · 任务收尾（每个任务交完自动做，不用提醒）

1. 记结论：本轮定下的口径、路径、结论，追加进本工作区 `.workbuddy/memory/MEMORY.md`
   写前先量：若写入会超 3000 字符，只做「腾位级」微压（合并同类行、删已失效行），**不整篇重写**；整篇重写属 B 档
2. 记坑：写清「症状→根因→正确做法→能不能写成代码里的判断」。写前先查用户级记忆有无同条，有就只写本空间的具体表现。**引用外部来源的事实（回单、聊天记录、网页）必须注明来源＋时点，并标一手/二手**（官方仓库、API 实测＝一手；博客、二手转述＝二手，须复核后才算数）；没来源标「待核实」。2026-10-29 实测：某博客称仓库 91.8k★，连接器查实为 97,009★
3. 清本轮中间产物：只删**本轮会话新建的**（解析 json、test_*.xlsx、__pycache__、临时 html），逐项列进收尾报告
   交付物（台账 xlsx、公文 docx、成图）一个都不许动；**来历不明的文件不删**，留给 B 档
4. 当天日志 `.workbuddy/memory/YYYY-MM-DD.md` 追加一条，只写结论不写过程
5. 不蒸旧日志、不动别的空间的任何东西

## B 档 · 空间收敛（记忆超 3000 / 日志超 10 份 / 用户发话时）

6. 先量：MEMORY.md 字符数、日志份数与合计字符、脚本数与可复用数、已有回滚点
7. 先快照：要改的记忆文件整份复制到 `.workbuddy/archive/memory-snapshot-日期/`，**快照路径写进最终报告**（这是回滚点）
8. 出清单等用户确认，不许边查边改
9. 压记忆到 3000 字符内：
   - 只留「换个会话、光看代码推不出来」的内容
   - **最重要的规则放文件顶部**——注入超预算时从尾部截断，头部最安全
   - 只合并、**不新写**：压缩过程里不产生任何新结论
   - **年代久不是删除理由**：删不删看是否失效，不看新旧
   - 删除优先级：过程叙述 > 已交付清单 > 过期快照 > 失效路径；**用户拍板的口径和否决记录基本不删**
   - **别处有副本的，删全文只留指针**（"细则见技能 X""过程见日志 Y"）——指针比分身安全，源头改一处不会漂
   - **原子写**：先写 `<文件名>.tmp`，写完再 `os.replace()` 换成原名。**不许直接覆盖**——写到一半被打断就成残档
10. 五项核验（任一不过就回滚），**清单必须由脚本产生，不许凭记忆列**：
    - 令牌：`python scripts/tokens.py check 旧.md 新.md` —— 自动抽数字/版本号/提交号/路径/URL/反引号标识符，旧有新无即报。确属故意更新的（如提交号刷新）用 `--allow` 豁免，并在报告写明理由
    - 推测标记：同一命令比对「可能/大概/估计/应该/似乎/待验证/待确认/未验证」数量。**新文件少于旧文件即报警**——压缩最常见的隐性损伤是把"可能是 X"写成"是 X"，关键词都在、确定性被拔高
    - 路径：新文件引用的每个路径逐一 exists 检查
    - 字符：`len()` 复测 ≤3000；用户级改动用 memcheck.py
    - 行数：`wc -l` 复测 ≤70。**字符达标但行数超同样算失败**——2026-10-29 实测压到 2936 字符却 71 行，memcheck 报"绿"但已破预算
11. 蒸日志：旧日志提炼要点写回 MEMORY 或单独索引；原文件移 `.workbuddy/archive/memory-日期/`，**不许删**
    **必须建 `归档索引.md`**：每份一行，写清字符数、里面有什么、怎么搬回——不建索引等于把东西藏起来
    「旧」的定义：当天日志不动、含未决事项（待确认/待办）的不动，其余才算旧
12. 清脚本：有 argparse 且代码无写死盘符路径 = 保留；写死盘符或无参数只能跑一次 = 移 `_archive/日期/`
    归档前查两处引用：① 各空间 MEMORY.md ② 自动化任务 prompt——有引用先改引用再归档，没查不许动
13. **搬家后复验**：第 11、12 步移动了文件，可能产生新的断链。
    重跑 `tokens.py` ＋路径 exists 检查，重点看 MEMORY.md 里指向被移动文件的引用
14. 删「已排除方案 / 否决记录」时，**否决原因必须跟着保留**（写进收敛记录）——只删结论不删原因，下次同样条件会把同样被否的方案再想一遍
15. 暂存类目录（_cleared-*、publish-*）删除前，逐个子目录说明里面装的是什么原件，用户确认后再删

## 通用规则

16. 拿不准是否过期，一律保留并标「待确认」；宁可留错，不许删对
17. 两条记忆互相矛盾，不自己选边，列出来给用户裁决
18. 只碰当前空间；动别的空间或用户级记忆先问；发现该上移用户级的条目（跨空间口径），列出问用户，上移前先量字符
19. 没快照不许删任何东西
20. 收敛记录：B 档收尾时在快照目录写「收敛记录-日期.md」——删了什么、为什么、可从哪份快照恢复。**这是审计账，不写进 MEMORY.md**
21. 交付一页报告：改了什么（带字符/文件数前后对比）、哪些没动及原因、矛盾待裁决项、回滚点路径、**豁免的令牌及理由**；没实测数字写「未验证」
    **压记忆必须附「处置表」**：只列**删除**和**合并**的条目，一条一行三列（原文摘要 / 处置：删·并入第 N 条·改指针 / 理由），原样保留的不列。只保证"一条没丢"却不给对照＝用户无法核，等于没核。用纯文本列，不用 Markdown 表格（粘进指令框会乱）
22. 压缩不宜频繁：MEMORY.md 每次重写都会使平台缓存失效、下一次请求变贵变慢——**攒够 B 档触发条件再做，不顺手就压**

## 脚本

| 脚本 | 用途 |
|---|---|
| `scripts/tokens.py extract 旧.md` | 看会抽哪些令牌（压缩前先用它心里有数） |
| `scripts/tokens.py check 旧.md 新.md [--allow a,b]` | 令牌缺失 + 推测标记减少；退出码 1 = 有问题 |

只依赖标准库。别用肉眼代替它——2026-10-29 实测：手工列的 32 个令牌号称"零丢失"，脚本一跑立刻发现漏了 3 个指针。
