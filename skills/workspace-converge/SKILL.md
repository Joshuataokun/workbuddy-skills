# 空间收敛（两档）

## 中文速览

```
A 档·任务收尾（每次自动）：记结论 → 记坑（先查用户级有无同条）→ 只清本轮新建的中间产物 → 当天日志追加一条
B 档·空间收敛（用户说「收敛」）：先量 → 快照 → 清单待确认 → 压记忆＋三重核验 → 蒸日志 → 清草稿脚本 → 收敛记录 → 一页报告
```

铁律只有一句：**候选区可以脏，正式记忆必须干净；拿不准就保留，宁可留错不许删对。**

## A 档 · 任务收尾（每个任务交完自动做，不用提醒）

1. 记结论：本轮定下的口径、路径、结论，追加进本工作区 `.workbuddy/memory/MEMORY.md`
   写前先量：若写入会超 3000 字符，只做「腾位级」微压（合并同类行、删已失效行），**不整篇重写**——整篇重写属 B 档
2. 记坑：写清「症状→根因→正确做法→能不能写成代码里的判断」。写之前先查用户级记忆有无同条，有就只写本空间的具体表现。**引用外部来源的事实（回单、聊天记录、网页）必须注明来源**，没来源的标「待核实」
3. 清本轮中间产物：只删**本轮会话新建的**（解析 json、test_*.xlsx、__pycache__、临时 html），逐项列在收尾报告里
   交付物（台账 xlsx、公文 docx、成图）一个都不许动；**来历不明的文件不删**，留给 B 档
4. 当天日志 `.workbuddy/memory/YYYY-MM-DD.md` 追加一条，只写结论不写过程
5. 不蒸旧日志、不动别的空间的任何东西

## B 档 · 空间收敛（记忆超 3000 / 日志超 10 份 / 用户发话时）

6. 先量：MEMORY.md 字符数、日志份数与合计字符、脚本数与可复用数、已有回滚点
7. 先快照：要改的记忆文件整份复制到 `.workbuddy/archive/memory-snapshot-日期/`，**快照路径写进最终报告**（这就是回滚点）
8. 出清单等用户确认，不许边查边改
9. 压记忆到 3000 字符内：
   - 只留「换个会话、光看代码推不出来」的内容
   - **最重要的规则放文件顶部**——注入超预算时从尾部截断，头部最安全
   - 只合并、**不新写**：压缩过程里不产生任何新结论
   - **年代久不是删除理由**：删不删看是否失效，不看新旧
   - 删除优先级：过程叙述 > 已交付清单 > 过期快照 > 失效路径；**用户拍板的口径和否决记录基本不删**
10. 压完三重核验，任一不过就回滚：
    - 关键令牌比对：列出必须原文保住的令牌（金额、版本号、路径、专名），逐条在新文件里查，少一个回滚
    - 路径核验：新文件里引用的每个文件路径逐一 exists 检查
    - 字符复测：`len()` 重新数，确认 ≤3000；用户级相关改动另跑 memcheck（有 memcheck.py 用它，没有就 len()）
11. 蒸日志：旧日志提炼要点写回 MEMORY 或单独索引；原文件移 `.workbuddy/archive/memory-日期/`，**不许删**
    「旧」的定义：当天日志不动、含未决事项（待确认/待办）的日志不动，其余才算旧
12. 清脚本：有 argparse 且代码无写死盘符路径 = 保留；写死盘符或无参数只能跑一次 = 移 `_archive/日期/`
    **归档前查两处引用**：① 各空间 MEMORY.md ② 自动化任务的 prompt——有引用的先改引用再归档，没查不许动
13. 删除「已排除方案 / 否决记录」类条目时，**否决原因必须跟着保留**（写进收敛记录）——只删结论不删原因，下次同样条件会把同样被否的方案再想一遍
14. 暂存类目录（_cleared-*、publish-*）删除前，逐个子目录说明里面装的是什么原件，用户确认后再删

## 通用规则

15. 拿不准是否过期，一律保留并标「待确认」；宁可留错，不许删对
16. 两条记忆互相矛盾，不自己选边，列出来给用户裁决
17. 只碰当前空间；动别的空间或用户级记忆先问；发现该上移用户级的条目（跨空间口径），列出问用户，上移前先量字符
18. 没快照不许删任何东西
19. 收敛记录：B 档收尾时在快照目录写一份「收敛记录-日期.md」——删了什么、为什么、可从哪份快照恢复。**这是删除的审计账，不写进 MEMORY.md**
20. 交付一页报告：改了什么（带字符/文件数前后对比）、哪些没动及原因、矛盾待裁决项、回滚点路径；没实测数字写「未验证」
21. 压缩不宜频繁：MEMORY.md 每次重写都会使平台缓存失效、下一次请求变贵变慢——**攒够 B 档触发条件再做，不顺手就压**
