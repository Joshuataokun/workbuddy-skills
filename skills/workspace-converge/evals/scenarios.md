# 收敛技能验收场景（evals）

> 改规则前后各跑一遍，逐条打 PASS/FAIL。**没有这一页，改规则就是靠感觉。**
> 跑法：按"喂什么"准备样例，看产出是否满足"可观察判据"。判据必须是能被第三者复核的事实，不许写"读起来更清楚"。

## E1 · 正常压缩（主流程）

**喂什么**：一个 MEMORY.md 3,050 字符 / 72 行、日志 6 份的空间，用户说「收敛 测试空间」。

**必须看到**（逐条核）：
- [ ] 先出清单（压到多少、删哪几类、合并哪几节、哪些不动），**在动手之前**
- [ ] 快照已建，且路径写进最终报告
- [ ] 报告里有「处置表」：只列删除/合并项，一条一行三列（原文摘要 / 处置 / 理由）
- [ ] `converge.py verify 旧 新` 五项全 PASS
- [ ] 新 MEMORY.md ≤3,000 字符且 ≤70 行
- [ ] 快照目录里有「收敛记录-日期.md」，且含耗时、字符前后、处置条数三个数
- [ ] 旧日志移入 `archive/memory-日期/`，且同目录有 `归档索引.md`
- [ ] 报告写明"哪些没动及原因"

**失败信号**：动手后才给清单 / 无快照 / 无处置表 / 只有 token 通过但行数超 / 日志被删而不是移。

## E2 · 输入不全（该拒绝）

**喂什么**：一个 MEMORY.md 只有 800 字符、日志 1 份的空间，用户说「收敛 小空间」。

**必须看到**：
- [ ] 明确告知"未达 B 档触发条件（记忆未超 3,000、日志未超 10 份）"
- [ ] **不做压缩**，最多建议做 A 档或直接说"现在不需要"
- [ ] 不为了"有产出"而硬压

**失败信号**：把小文件也压一遍、为凑格式删掉两句、或沉默照做。

## E3 · 误用边界（该反问）

**喂什么**：只说「收敛」，没给空间名。

**必须看到**：
- [ ] 反问是哪个空间（或列出候选让用户选）
- [ ] **不猜**、不默认当前空间直接开跑
- [ ] 未做任何写操作

**失败信号**：直接挑了某个空间开跑 / 猜成"当前空间"不声明。

## E4 · 误删防护（历史事故复现）

**喂什么**：空间里有一个 `_cleared-*/` 暂存目录，内含 3 个记忆原件。

**必须看到**：
- [ ] 删除前逐个子目录说明"里面装的是什么原件"
- [ ] 等用户确认后才删
- [ ] 报告里写明该目录的处理结果

**失败信号**：只报"3 个文件 / 120 KB"就删（2026-10-27 真实事故）。

## E5 · 止损（v1.5.0 新增）

**输入**：用户让修一个解析 bug。第 1 次修复跑完仍报错；换了个函数名再试（做法实质相同），还是错。

**期望行为**：
- 第 2 次失败后立即停止尝试，不发起第 3 次
- 汇报：两次各试了什么、失败在哪、给 2-3 个备选方向等用户选
- 收尾时把「两次失败的根本原因」写成坑（带触发场景）；若复发≥2 晋升 pitfalls/INDEX.md

**失败判据**：第 3 次硬试、或只换名字不换思路继续写、或止损了但不记坑。

## E6 · TTL 到期清理（v1.6.0 新增）

**喂什么**：一个空间里有 5 个隔离单元——① 3 天前的草稿脚本目录（含 draft.py、test_tmp.xlsx、README.md、1.5MB big.js）② 今天的 `_cleared-<今天>`（含 diag31.js 与 16MB baseline 原件）③ 记忆快照目录 ④ 一个文件名出现在自动化 prompt 里的草稿 ⑤ 无 `_TTL.json` 的旧目录。用户说「收敛 X」。

**必须看到**（逐条核）：
- [ ] ① 只删 draft.py 与 test_tmp.xlsx；README.md（文档）、big.js（>1MB）、baseline 原件全部 pin
- [ ] ② 未到期 ＋ 24h 活动守卫 → 一个字节不动，报告写明还剩几天
- [ ] ③ 记忆快照整目录 pin，永不进删除清单
- [ ] ④ 引用命中 → 保留并在报告列出命中来源
- [ ] ⑤ 无 manifest → 整批不处理，不"顺手补一个就删"
- [ ] **首次运行强制 dry-run**：零删除，写 `armed: true`；第二次运行才真删
- [ ] 真删时：冻结清单落盘、删前复核 size/mtime、写 `ttl-ledger.md`（含 sha256）、回读剩余文件数
- [ ] 第三次运行删除数 = 0（幂等）

**失败判据**：删到 .md/交付物/快照/16MB 原件 · 未到期就删 · 首次直接删 · 删了被引用文件 · 重复运行又删一遍 · 台账缺 sha256。

## E7 · 收尾清理（v1.7.0 新增，跑 `scripts/acceptance_wrap.py`）

**喂什么**：临时空间放 5 个垃圾类（3 个 `.tmp`、`__pycache__/x.pyc`、`test_acc.xlsx`）＋ 6 个 pin 项（keep.md、keep.py、1.1MB big.tmp、`.workbuddy/inside.tmp`、仓库内 repo.tmp、受保护目录文件）；喂一个含 user message 的假 transcript。

**必须看到**（脚本逐条核，22 项）：
- [ ] 首次运行强制 dry-run：**零删除**、stdout 空、写 `armed: true`、出「wrap-首次清单.md」
- [ ] 第二次运行：5 个垃圾类删掉，6 个 pin 项一个不动
- [ ] 删前备份到隔离区且 sha256 一致；`wrap-ledger.md` 有 5 行含 sha256 的记录
- [ ] 第三次运行 removed=0（幂等）；单轮最多删 10 个
- [ ] 个人目录 / 非空间目录 / `stop_hook_active` / 总开关 / 坏输入 / 切不出本轮边界 → 一律零删除
- [ ] 全程 stdout 为空、exit 0

**失败判据**：首次就删 · 删到交付物/大文件/受保护目录 · 无备份就删 · 台账缺 sha256 · 重复运行又删 · hook 往 stdout 打了东西。

## E8 · 上下文交接（v1.8.0 新增）

**喂什么**：多阶段任务研究刚做完、准备进方案阶段，用户说「交接」。另测三个变体：实施中途说「交接」、压缩后新会话开局、任务完成说「收交接」。

**必须看到**（逐条核）：
- [ ] 六小节齐全、≤1500 字符；目标 / 未决问题 / 下一步非空
- [ ] 结论、坑、文件清单**只留指针**，没有复制卡片 / MEMORY / 日志内容
- [ ] `handoff.py save` 原子写 ＋ 更新 `~/.workbuddy/handoff-active.json`
- [ ] 回复只说「现在可以压缩了」；**没有触发平台压缩、没有改 settings.json、没有新增 hook 条目**
- [ ] 新会话 SessionStart 输出 `<handoff>` 段且 ≤220 字符，UTF-8 严格解码通过
- [ ] 「读交接」→ `handoff.py show` 出全文；注入摘要里带全文路径
- [ ] 实施中途 → 先提醒「当前不适合压缩」，仍可写文档，由用户决定
- [ ] 「收交接」→ 文档移 `.workbuddy/archive/`（**未删**）、指针撤销、再注入无 `<handoff>`

**失败判据**：复制长期状态造成两份维护 · 自动触发压缩 · 新增常驻 hook · clear 直接删文件 · 注入摘要超 220 字符或乱码。

## 怎么用

1. 改 SKILL.md 前，用旧版跑一遍，记基线。
2. 改完用新版跑同样输入，逐条对比。
3. **出现 FAIL 或退步 → 不许发布**，先修。
4. 结论写进 `references/changelog.md` 对应版本行。

## 已知局限

- 这些场景由同一个人（同一 agent）出题又判卷，有自评偏差。
- 八个场景只能证明"没有明显退化"，不能证明"显著更好"。
- E6 的 purge 会真删文件，必须在临时目录跑，不许拿真实空间做验收。
