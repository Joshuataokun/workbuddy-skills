# 报告格式与验收

> 完整规格见 `spec-v9.3.md` 第 8–10 节。本文件是写报告时的速查模板。

## 一、报告硬约束

- Markdown，**48 行以内**。
- **只输出在对话里，不往任何工作空间写报告文件**。
- 占用地图数字**每次重测**，不许照抄示例；按体积降序；每行有「性质」列，写清「这是什么、删了会怎样、按什么期限自动清」，期限天数从策略读。
- 结尾固定一行回收站占用（直读 `$Recycle.Bin`，不用 Add-Type/COM），写明「清空回收站才真正释放空间，这一步由用户手动做，不代劳」。
- 报告里不出现工具内部细节（脚本路径、临时文件名）。

## 二、首两行（固定句式）

```
本次清平台缓存 X MB + 到期回滚/备份 Y MB + 隔离区到期释放 Z MB + 已删空间隔离 N 个 / W MB（均已回读校验；进回收站的注明未真正释放）；未删任何活空间、会话、任务、对话正文；另有 K 项候选合计 W GB，等你口令
耗时：M 分 | 结果：OK / PARTIAL | 空间 N 个 / 活会话 M 个 / 磁盘 C 剩 xx GB、E 剩 xx GB | 下批到期：类目 还剩 x 天
```

- 四者任一为 0 时省略该项；隔离区无到期批次写「隔离区无到期批次」；回滚无到期写「回滚备份无到期」；无候选写「无已删空间候选」。
- V2/V4/V6/V8/V10/V11 任一 ✗ → 结果 `PARTIAL`，置顶。应用自身写入导致的变化要注明来源，不算越界但如实标 ✗。

## 三、五档结构

1. **占用地图**：两张表（目录 Top 8 + 回滚备份 Top 5 会话）。Top 5 列：会话 id 前 8 位 / 所属空间 / 体积 / 文件数 / 最后写入 / 距到期天数 / 占比最大的扩展名。只读元数据，**不读会话正文**。
   - 固定两句：回滚备份是「编辑前的文件副本」，删除不影响对话正文与任务本身，只影响该会话撤销/回滚；v9.2 起有期限到期自动清，想长期留说「保留回滚 <id前8位>」。
2. **已自动处理**：缓存逐类「删前→删后，释放 MB」+ Crash-Log 轮转 + 隔离区释放（批次/文件数/MB/是否真正腾出空间）+ 到期回滚备份逐类 + 已删空间隔离（候选/移入/排除原因/批次号/到期日）。
3. **可清理候选**：类目 / 数量 / 占用 / 口令。不列「回滚备份」（已自动），改为一行「未到期回滚 X 个 / Y MB，最近一批还剩 x 天」。末尾固定：「说对应口令我才执行，会先出清单、进隔离区、7 天后自动真删。」
4. **建议收敛**：只列超预算/贴线/日志偏多。末尾：「需要我收敛哪个，回一句『收敛 <空间名>』。」
5. **需你确认**：E 类临时目录空间、cwd 告警、无 manifest 的隔离批次、被保护条件拦下的会话、应用重建的空壳空间、可用空间未真正释放的提示。

**已删空间候选单独一张表**：目录名 / 体积 / 文件数 / 最后写入 / 活会话 / 显示名 / 是否候选 / 排除原因。表下固定一句：「本表只读；常规轮按 2.7 自动移入隔离区、7 天后释放，想立即试跑说『清已删空间』。候选通常只有两三个近空目录，合计不到 0.05 MB，主要作用是机制补齐而不是腾空间。」

验收压一行：`V1✓ V2✓ … V11✓`。

## 五、收尾（写文件，不写报告）

1. `$WB\cleanup-runs\<yyyyMMdd-HHmm>.json`：四类动作删前/删后/差值、refused、skipped_changed、隔离区释放明细、retention 明细、**spaceQuarantine 明细**、占用地图摘要、耗时。**不含会话标题与文件名。**
2. 更新 `$WB\cleanup-state.json`：`lastRunAt` / `lastStatus` / `lastFreedMB` / `lastReleasedMB` / `lastRetentionMB` / `lastSpaceQuarantineMB` / `lastSpaceMap` / `quarantine.batches` / `retention.nextDue` / `spaceQuarantine.nextDue` / `history` 追加一条（保留 26 条）。
3. 自动化 memory 只写一行：`YYYY-MM-DD HH:MM 执行成功，清缓存 X MB + 到期回滚/备份 Y MB + 释放隔离 Z MB + 已删空间隔离 N 个，未删活空间/任务`（无释放写「隔离无到期」「回滚无到期」「无空间候选」）。
4. **删锁文件**（try/finally，异常也要删）。
