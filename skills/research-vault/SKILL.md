# 调研沉淀库（Research Vault）

## 中文速览

解决一个具体痛点：**联网/GitHub 调研花了很多时间，几轮对话后模型就忘了、下次要重新查**。

根因不是模型记性差，而是把「对话窗口」当记忆用——原始资料又长又杂，堆在窗口里必然被挤掉。做法是**当场把结论外置到资料库这个持久层**，下次用一句话语义召回。资料库天然跨设备、可被 AI 检索，正好补上本地文件的两个短板。

本技能只负责「调研沉淀」这套流程与模板；**具体读写资料库一律调用系统内置的 `library` 技能**（本技能不重复实现它的命令，也不硬编码它的内部路径）。

## 一、什么时候用

用户说这些话时触发：存进调研沉淀 / 存调研 / 把这次调研存起来 / 调研归档 / 这次调研留个底 / 把调研结论存起来；查调研沉淀 / 查一下之前调研的 X / 资料库里关于 X 的结论 / 之前是不是查过 X。

边界：

- 目标是**调研得来的网页、仓库、资料、经验**，不是本地项目状态 → 项目进度/口径/待办走 `my-project-card`。
- 存的是**内容型笔记**（文档、链接），不是技能代码 → 技能跨设备同步走 GitHub 仓库，别往资料库塞技能。
- 不替代 claude-mem 那类代码会话记忆；本技能面向"调研资料"。

## 二、目录结构（一个项目空间一个文件夹）

```
调研沉淀/                          ← 唯一总根，检索时锁定它
└── <项目名>/                      ← 一个项目空间一个文件夹
    ├── 00-索引.md                 ← 总览：结论清单 + 来源表 + 更新时间（模型先读）
    ├── 结论/                      ← 四栏结论卡片 doc，标题不带冗余前缀
    ├── 来源/                      ← 剪藏的 link 节点
    └── 待核实/                    ← 剪藏失败、无来源的结论
```

**项目名怎么取**：读 `~/.workbuddy/workspace-display-names.json`，用当前工作区路径对应的 `displayName`（用户右键改过的空间名）；没有记录就用空间目录名（如 `学习无名`）。同一项目每次都落到同一个文件夹，不散落、不重复建。

## 三、两个动作

### 存（capture）

调研告一段落，先定位/建好项目文件夹（含四个子目录），然后：

1. **原始网页 / GitHub 页** → 剪藏成 `link` 节点。注意 `doc.create-link` **不支持 `--parent-id`**，建完必须 `move-node` 到该项目「来源/」，否则会掉在库根目录成为游离节点（1.0.0 的散乱根因）。
2. **结论卡片** → 一个 `doc` 节点，每条结论严格四栏：**结论 / 依据 / 被否方案 / 来源**，建到该项目「结论/」。只写会复用的判断，不堆原文。
3. **更新 `00-索引.md`** → 追加本次结论标题 + 一句话 + 来源数 + 日期。这是"快速调用"的关键，不能省。

字段规则、命名约定、归位命令、fallback 见 `references/capture-and-recall.md`。

### 取（recall）

用户问"之前调研过 X 吗"时：

1. 确定项目文件夹 → `targets` 锁定它做**语义检索**（不是关键词）。
2. **先读 `00-索引.md`**（一份短清单），按图索骥定位具体卡片，不扫全文。
3. 把命中结论按"结论 + 依据 + 来源"列出，**标出已被更新/推翻的旧结论**。
4. 没找到就直说没找到，不拿通用知识编造冒充"资料库里的"。命中只给片段，要全文时按 `nodeKind` 读回节点。

## 四、首次使用

先确保总根「调研沉淀」存在（folder），再确保当前项目的文件夹和四个子目录存在；都已存在就直接复用，不问、不重复建。完整步骤见 `references/capture-and-recall.md`。

## 五、铁律

1. **一个项目一个文件夹**——按 workspace 显示名取名，同一项目只落一处。
2. **剪藏必须归位**——`create-link` 不认落点，建完立刻 `move-node` 到「来源/」，不许留在根目录。
3. **结论四栏带来源**——"被否方案"不能省（省了会把推翻的方案捡回来），没来源标 `[待核实]` 进「待核实/」。
4. **每次更新索引**——`00-索引.md` 是快速召回的入口，存完不更新等于没存好。
5. **召回先读索引**——锁项目文件夹、先读索引、再取卡片；没命中就说没有，绝不把模型记忆伪装成库里的。
